- 测试、工具随域：过渡目录 `_import/qian/tests/` 下的 Qian.Events.Tests、Qian.Audit.Tests、Qian.Audit.Native.Tests、Qian.Audit.Native.AotTests（不在解决方案里），`_import/qian/tools/Qian.Audit.Native.Probe`；仓库根 `tests/` 下的 Kun.EventBus.Tests、Kun.EventBus.Abstractions.Tests、Kun.Audit.Tests、Kun.Auditing.Tests、Kun.Saga.Tests（随 Kun.Saga 归档）、Kun.IntegrationEvents.SchemaGen.Tests。过渡目录里随这一批搬出的 .NET 项目共 10 个（5 个包、4 个测试、1 个工具），依赖容器夹具的测试项目除外：它们原地换名、留在过渡目录，随 B9 搬（S1-KUN-028）。门禁样例（`_import/qian/tests/gates/` 下）不随这一批搬，原地跟着换包名、保持能编过，整组归 B10（S1-KUN-029）。
- Qian.Audit.Abstractions 链接 `_import/qian/packages/Common` 下的共享源文件：搬走它时引用路径跟着改，共享源文件本身不在这一批搬，归 B10（S1-KUN-029）。

破坏性变更随 PR 记：本批每个 PR 的破坏性变更写进仓库根 `CHANGELOG.md` 的 `[Unreleased]`。理由是发版脚本 `scripts/release.sh` 第 4 段把 `[Unreleased]` 变成版本段，首个合并版的版本说明从这里来（S1-KUN-022）。

开工前要补的事：

- 蓝图 §1.2 的未核实事项落在这一域的：两边的订阅器只读了结构，没有读完实现。合 RabbitMQ 的发布与订阅之前读完。
- 档位按依赖图复核（仓库根 `scripts/check_deps.py`，项目文件里的 `KunTier` / `KunRole`）：
  - Kun.Audit.EntityFrameworkCore 由内核档转平台档，并入 Kun.Auditing 的事务拦截器。Kun.Auditing 的 IL2091 是 B3 没给它开 AOT 的原因，并进非 AOT 的平台包之后不再有这个问题。
  - Kun.EventBus.EntityFrameworkCore 记内核档：Qian.Events 的投递循环现在依赖 Qian.Data.Abstractions 与 Qian.Tenancy.Abstractions，B5 之后只能依赖内核档的 Kun.EntityFrameworkCore 与 Kun.MultiTenancy。B5 若留下 Qian.Events 上的两条规则 K 例外（`Until` 已改为 B6），这一批去掉。
  - B5 把 Kun.EntityFrameworkCore 改记内核契约，它对内核提供者 Kun.EventBus 的直接依赖（Outbox 的写入端、缓冲器、消息实体）记了一条临时例外（规则 D，`Until="B6"`，S1-KUN-024）：这一批把 Outbox 写入契约并进 Kun.EventBus.Abstractions，Kun.EntityFrameworkCore 改指契约，这条例外去掉。
  - Kun.EventBus.RabbitMQ 现在在 AOT 清单里（`IsAotCompatible`）；换成 Qian.Events 的实现之后能不能留在清单里，以 AOT 冒烟宿主为准，留不下就移出清单并在 PR 正文写明。
- 平台分析器 QIAN0006（事件发布范围）按全名找 `Kun.EventBus.IIntegrationEventBus`、`Kun.EventBus.Outbox.IOutboxWriter`、`Kun.EventBus.Outbox.IIntegrationEventOutbox` 与 `IntegrationEventBuffer`，事件总线改动时跟着改；events 一组 8 个门禁样例照旧按预期报错。
- 信封的线上形状以 `_import/qian/contracts/v0/event-envelope.schema.json` 为准，并入 Kun.EventBus.Abstractions 时不变；`contracts/data/v1/record-changed-envelope.schema.json` 里写着这一域的类型名，跟着换。
- 对前端有没有影响：`plugins/` 下 qian.events、qian.audit、qian.audit.native 三个组件的清单里写着入口类型与程序集名，随包换；组件 id 不变。`packages/qian-cli` 的 `test/private-feed.e2e.mjs` 里有 `using Qian.Events;` 与 `AddQianEvents()`（对包源上已发布的包编译，B4 的做法是不改它），`README.md` 写着 Qian.Events。改之前先看。
- 组件版本：`_import/qian/plugins/` 下 system 级组件（`policy.tier` 为 system、`runtime.form` 为 module 的非骨架组件，口径同 `scripts/sign-system-revisions.py` 的签名清单）的文件夹里任何文件一改，目录摘要就变：清单里的入口类型与程序集名随包换、README 改一个字都算。按 S1-DEC-037 的裁决（R167），要连带升该组件的版本，版本号继续唯一对应文件夹的内容。这一批碰到的 system 级组件：qian.events、qian.audit。
  - 升版本：同一个组件被先后几个 PR 改到，每个 PR 各升一次，不看前一次升的版本部署过没有（何时部署另定，可能落在任意两次合入之间）。升哪一位照 R167 采纳的做法：只改说明文字升修订号；对外行为不变的改动（清单里的入口类型与程序集名、契约文件里的 Schema 键）与兼容的增加（加权限点、可选字段）升次版本；对外行为变了、不兼容（线上契约、权限点、配置 Schema）升主版本。
  - 发布的 HTTP 契约会随换包名漂移：组件 Schema 的键取类型程序集限定名的哈希（`Qian.Capabilities.AspNetCore` 的 `AspNetCoreHttpContractSource`），发布契约三份，是 `plugins/qian.registry`、`plugins/qian.tenancy`、`plugins/qian.tenancy.signup` 下的 `contracts/http-v1.openapi.json`。在主干 691eabad 上按键反推，这一批要换的包里没有类型出现在这三份契约里，不会漂；换包名之后仍以 CI 上三处漂移测试（Qian.Registry.Tests、Qian.Sample.Crm.Tests、Qian.Tenancy.Signup.Tests）通过为准，漂了就重新生成并照上面升版本。
- 文档：归档 Kun.Saga 会牵动仓库根 `docs/` 里讲 Saga 的两页（设计说明 `why-saga.md` 与指南 `orchestrating-sagas.md`），留还是删由这一批的方案定，删就是改 `docs/` 的布局；讲 Outbox 与审计的页面、`README.md` 的归档名单与根 `AGENTS.md` 的运行时约定（Outbox、Saga 两段）也要跟着改。
