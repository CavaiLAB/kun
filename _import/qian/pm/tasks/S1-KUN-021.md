## 背景

ADR-023 D23.15 的阶段 3，逐模块的归并对照在 D23.9，命名规则在 D23.8。一域一批，自底向上：错误模型与运行时基础 → 租户上下文与数据 → 事件与审计 → 安全、身份、网关 → 权限 → 配置、存储与文件、测试支持 → 只在 Qian 的平台组件及宿主、工具、样例。同一时间一个域只有一个归并批次，功能任务避开正在归并的域。本任务是总任务，各批次在阶段 2 结束后单独建档。

蓝图的归并对照来自只读核实，没有跑构建与测试；§1.2 列的未核实事项可能改变个别模块的归并动作与档位。

估算是占位：蓝图写的是「数周量级，没有拆解估算」，阶段 2 结束后按域建任务再估。

2026-11-17 补（S1-DEC-038 D17、D18）：目标仓库是 `CavaiLAB/kun`，七个批次对应迁移执行计划的 B4–B10。前端不再是本任务之后的最后一批，它并行迁往 `CavaiLAB/qian`；导入子目录 `_import/qian/` 在各域批次与前端目录移出（计划的 B11）都完成之后删除。

2026-11-19 补（B3 的第 6 个 PR）：七个批次已按域建档并估算，挂在本任务下（本任务的 depends 加上了它们），依次串行，第一批依赖 S1-KUN-020：B4 是 S1-KUN-023（8d），B5 是 S1-KUN-024（11d），B6 是 S1-KUN-025（8d），B7 是 S1-KUN-026（13d），B8 是 S1-KUN-027（5d），B9 是 S1-KUN-028（8d），B10 是 S1-KUN-029（8d），合计 61 人日（54–67）。每批的范围按 D23.9 逐个包列出，来源目录、公共 API 清单与引用方都在主干上核过；§1.2 的未核实事项、档位复核、依赖门禁现存 11 条例外各在哪一批去掉、归档名单与停发的 8 个包名、运行期字面、对前端有没有影响与平台文档站的钉，都写进了各批的背景与验收。本任务 estimate 里的 20d 是拆批之前的占位，没有改成合计，免得看板按人日加权时与批次任务重复计数。七个批次只管 .NET 项目：过渡目录里的非 .NET 内容（看板、文档站、前端工作区、契约、Schema、TCK、组件与 profile、部署清单等）怎么搬出、导入子目录什么时候删，不在任何一批里，另定。
