## 背景

[契约草案](../../docs/prd/specs/authz-remote-interface.md)第 13.2 节第 4 项。[S1-DEC-045](S1-DEC-045.md) D9 定了客户端包先出 TypeScript 与 .NET 两种。条件：两个谁在前看第一个使用方；接第一个历史系统时再看要不要出 Java。

谁在前后来问过。产品负责人 2026-11-26 定（[S1-DEC-048](S1-DEC-048.md) D3）：先 .NET，列给他的理由是工作区服务照现在的设计是 .NET 写的。落到任务上是整理时定的：本任务排在 .NET 的那一个（[S1-AZ-015](S1-AZ-015.md)）后面，依赖里加了它；一致性用例与替身服务照草案第 7.1 节的提议由先做的那一个带，现在就是 S1-AZ-015，本任务对着它跑。

一个包，两个入口，按打包条件分开（草案第 7.2 节）：

- Node 的入口给登记过的后端服务用：用机器身份，能问自己，也能替别的主体问；结果可以当执行的依据。
- 浏览器的入口给管理端与页面插件用：只带页面自己的登录会话，只能问自己；结果只用来决定显示什么，判定在后端的入口上做。

浏览器的入口里只用现有 `GET /api/authz/me/permissions` 的那一部分不等契约定稿，也不受两个包先后的影响，照旧可以先做。浏览器的入口里其余要等契约定稿的部分，即预判、本人允许的动作、解释自己，要不要赶在 .NET 的包之前单独出，没有问过；匠心的管理端要用到的时候再看。

没有定的：包名随契约定稿（[S1-AZ-011](S1-AZ-011.md)）；包发到哪个源没有定，开工时先问。

## 验收

- [ ] 一个包两个入口；浏览器的入口里没有任何取机器凭据的代码，在构建产物上核对
- [ ] Node 的入口：取、缓存、续期机器身份的访问令牌；执行前的判定、预判、代问
- [ ] 浏览器的入口：本人持有的权限点、本人允许的动作、预判、解释自己；接口上没有「主体」这个参数；带登录会话的 POST 由包带上防伪的请求头
- [ ] UT（D4）：执行前的判定不缓存；预判照平台在响应里给的时长缓存，可以关掉，不可以调长；缓存只放内存
- [ ] UT：缓存的键里，带着本人的令牌问时主体用令牌的摘要，不用包自己从令牌里读出来的字段
- [ ] UT：判不了一律拒绝，没有放行的开关：不是 200 的响应、超时、连不上、解析不了、缺布尔的放行结果、响应自己对不上，都当作判不了；Node 的入口告诉调用方是「判不了」，浏览器的入口按没有这项权限显示
- [ ] 超时、重试与连续失败以后的短路照草案第 8 节；数字以定稿的契约为准
- [ ] 对着一致性用例与替身服务跑通；用例与替身由 S1-AZ-015 交付（见背景）
- [ ] 包的说明写明两个入口各自能做什么、不能做什么，以及各人 DSH 实例里的代码不用 Node 的入口
