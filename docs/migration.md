# 迁移与归并

> 状态：规划稿（2026-11-17）。依据是合并蓝图：`idadawn/qian` 仓库的 ADR-023，现在在一个待合并的 PR 里，状态是 Proposed。本文是它的摘要，并记下迁到本仓库之后蓝图要修订的地方。数字取自 2026-11-17 两个原仓库的主干。

## 1 两个来源

| | 原 Kun | 原 Qian 的后端 |
|---|---|---|
| 仓库 | `idadawn/kun` | `idadawn/qian` |
| 是什么 | .NET 10 云原生微服务框架 | 建在 Kun 上的多租户平台 |
| 规模 | 35 个模块，约 2.4 万行 | 56 个包项目，约 6.4 万行；87 个测试项目 |
| 版本 | 日历版本 | 语义化版本，各包同一版本号 |
| 发布位置 | nuget.org | GitHub Packages |

两边合计 91 个包，合并之后是 84 个：内核档 40 个，平台档 44 个。

此前 Qian 精确钉住 Kun 的版本，Kun 每修一处，Qian 就要跟着升一次版本。合并之后，改动和修复在同一个 PR 里过 CI。

## 2 已定

产品负责人 2026-11-17 的裁定：

| 事项 | 裁定 |
|---|---|
| 方向 | 原 Qian 的后端并入 Kun |
| 包族 | `Qian.*` 并入 `Kun.*`，一个包族，一条日历版本线 |
| 方式 | 不是原样搬运。清点两边重叠与可以复用的部分，同一职责合成一份 |
| 定位 | Kun 重新定位，表述见 [README](../README.md) |
| 租户号 | 统一用 Guid。原 Kun 接受任意标识，并在缺租户时回落到一个缺省租户；合并之后只收 Guid，缺租户即拒绝 |
| 前端 | 前端框架由 yue 更名为 qian，和后端改名放在同一个冻结窗口里，排在按域归并的最后一批 |
| 「Qian」的用法 | 只作前端框架的名字。运行期的字面保留不改，见第 4 节 |
| 许可 | .NET 包族、命令行与前端包全部用 MIT。已经按原许可发布的旧版本不受影响 |
| 发布渠道 | 内核档照旧发 nuget.org；平台档在正式对外发布之前只发 GitHub Packages，之后全族上 nuget.org。发到公共包源的包撤不回来，所以平台档先走私有包源 |
| 归档 | `Kun.Saga`、`Kun.Sandbox`、`Kun.Dapper`、`Kun.Infrastructure`、旧线的 `Kun.Storage` |
| 去处 | 合并后的 Kun 放在本仓库 `CavaiLAB/kun`，先建仓库写文档，代码分批迁入 |

## 3 分几步

蓝图把归并分成几步，每一步结束时两边的测试都在同一条流水线上通过，出了问题知道是哪一步引入的。

| 步骤 | 做什么 | 完成的标志 |
|---|---|---|
| 蓝图确认 | 蓝图转为已接受；回写受影响的决策记录与两个原仓库的代理入口说明 | — |
| 冻结与导入 | 开着的 PR 全部合入或关闭；带着历史把两边的代码导入同一个仓库。这一步不改任何包名 | 导入完成，原仓库只读 |
| 构建并轨 | 一个解决方案；原来的包引用改成项目引用；中央包版本取高的一边；依赖门禁改成显式的档位表；CI 并轨。仍不改包名 | 两边全部测试与门禁在一条流水线上通过 |
| 按域归并与改名 | 一个域一批，自底向上：错误模型与运行时基础 → 租户上下文与数据 → 事件与审计 → 安全、身份、网关 → 权限 → 配置、存储与文件、测试支持 → 只在原 Qian 的平台组件及宿主、工具、样例。最后一批是前端更名 | 每一批：这个域的每个职责只剩一套公共 API，归档的类型移出解决方案，全量测试通过 |
| 首个合并版 | 按日历版本发版；旧的 `Qian.*` 包标为弃用并指向新包名 | 包发布成功 |

两条要点：

- 改名之前先改门禁。现在的依赖门禁按包名前缀判定，包名一改就会不声不响地失效，所以要先换成显式的档位表，并带自测。
- 同一时间一个域只有一个归并批次，功能开发避开正在归并的域。

## 4 名字：哪些改，哪些不改

| 类别 | 内容 | 处理 |
|---|---|---|
| 代码层 | .NET 包名、命名空间、类型名里的 `Qian`、分析器诊断号、构建属性 | 跟着改成 Kun |
| 运行期与生态的字面 | 组件 id 前缀 `qian.`；数据库里的 schema 名；Cookie 名、交换机名、缓存键前缀；契约里的标识与扩展键；清单与配置的文件名（`.qian-plugin/plugin.json`、`qian.profile.yml`、`qian.patch.yml`）；`qian` 命令行 | 不改，与包名脱钩 |
| 前端 | yue 的全部包名、目录、样式变量前缀、测试标识、脚本名 | 改名为 qian |

第二类不改，是因为它们已经落库、上线或冻结：改数据库的 schema 名要迁移数据，改 Cookie 名会让在线会话全部失效，改契约标识等于发一个新的主版本，而这些改动不带来任何功能。它们今后只是历史字面，不再表示产品名。

## 5 对现有使用方的影响

首个合并版对原 Kun 包的现有使用方是一次破坏性升级：内置错误码改名、错误类型的形状变了；租户号只收 Guid、没有缺省回落；网关由可执行程序变成库；消息队列的交换机、路由键与消息体改用原 Qian 的现值；有几个包名换了实现；八个包名停发。旧版本留在包源上不动。

用源码引用 Kun 的下游，提议在归并开始之前先钉住合并前的最后一个 Kun 版本。

## 6 还没定的

蓝图里还没定的：

- 蓝图整体的确认。确认之前不动代码和仓库结构，两个原仓库照现行规则开发。
- 租户上下文端口里租户号的属性类型，是否由字符串改成 Guid 类型。
- 冻结窗口放在什么时候。蓝图的提议是放在原仓库当前在途的里程碑收口之后。
- 用源码引用 Kun 的下游怎么安排。

迁到本仓库之后，蓝图要修订的：

| 蓝图现在的写法 | 现在的情况 | 要定什么 |
|---|---|---|
| 合并后的仓库是 `idadawn/kun`，把原 Qian 整棵树导入它的一个子目录 | 合并后的 Kun 放在 `CavaiLAB/kun` | 两边的历史怎么导入这个新仓库 |
| 一个仓库放下全部：.NET 包、前端工作区、文档站、任务看板、契约、部署清单 | 前端单独一个仓库 `CavaiLAB/qian`，另有平台总览仓库 `CavaiLAB/jiangxin` | 前端什么时候拆出去；命令行与 TypeScript 运行时放哪里；文档站、任务看板放哪里 |
| 前端的 8 个包叫 `@idadawn/qian-<原名>` | 包名前缀跟着 GitHub 所有者走，所有者换成了 CavaiLAB | 前缀用什么 |
| 平台发行版不单独起名 | 整个平台定名「匠心智能体平台」 | 文档里的叙述按新名字写 |

## 7 旧地址

`CavaiLAB/kun` 这个地址在 2026-10 Kun 迁到 `idadawn/kun` 之后一直跳转过去。本仓库建立之后跳转失效。在代码迁入本仓库之前，取 Kun 源码请用 `idadawn/kun`。
