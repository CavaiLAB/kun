## 背景

产品负责人 2026-11-27 答第二张表「都按建议」（登记在 [S1-DEC-050](S1-DEC-050.md)）。第二张表第 3 条的建议是「认证页在匠心用新的基础组件重做一套，Kun 只出接口，Kun 里冻结的那一版留作缺省；先做找回密码与验证码登录，其余随后；新页面上线以前照冻结的样子用。」同一天他发来新方向（登记在 [S1-DEC-051](S1-DEC-051.md)），原话里有「Kun 保持现有基础框架和接口，继续负责认证、会话和权限。登录、工作区和管理端等产品页面统一放到 jiangxin 重新设计，旧布局和样式可以淘汰。」与「先列清各个包的去向，修订文档，再用登录页跑通前后端流程。」照此，匠心重做的登录页要能照本仓库的公开契约接上，本任务把登录与会话用到的接口补进公开契约。做法比照 [S1-IDP-030](S1-IDP-030.md)。

现状（对着代码读的，2026-11-27）：登录与会话的接口有端点，公开契约里没有。`contracts/identity/v1/` 里只有目录查询与新增成员两份 OpenAPI 和事件 Schema；注册页用的申请人接口在 `plugins/qian.tenancy.signup/contracts/http-v1.openapi.json` 里，已经有契约。没有契约的：

- 身份服务的账号接口（`src/Kun.Identity.Server/IdentityAccountEndpoints.cs`，前缀 `/api/identity`）：`GET /csrf`、`GET /captcha`、`POST /login`、`POST /login/select`、`POST /login/password`、`POST /session/switch`、`GET /me`、`POST /me/password`。
- 连接器登录（`IdentityConnectorEndpoints.cs`）：`GET /connectors`、`GET /connectors/{connectorId}`、`POST /connectors/{connectorId}/begin`、`GET /connector-flows/{flow}`、`POST /connector-flows/{flow}/signin`、`POST /connector-flows/{flow}/bind`，以及连接器的回调路由。
- 会话（`IdentitySessionEndpoints.cs`）：`GET /sessions`、`POST /sessions/{sid}:revoke`、`POST /persons/{id}:revoke-all`、`GET /online-users`。
- 依赖方会话（`src/Kun.Identity.Client/IdentityClientHosting.cs`，前缀缺省 `/auth`）：登录、回调、登出、`csrf`、`session`、`session/refresh`。
- OIDC 协议端点（`/connect/authorize`、`/connect/token`、`/connect/userinfo`、`/connect/logout`）照标准走，不写 OpenAPI，契约 README 里写明照哪几份标准、平台私有的扩展参数有哪些（认证页规格 §8 D11 的 `tenant_hint`）。

登录页与认证页要的新接口（找回密码、验证码登录、账号会话登出、工作空间候选带租户状态等）在 [S1-IDP-019](S1-IDP-019.md)、[S1-IDP-020](S1-IDP-020.md)、[S1-IDP-006](S1-IDP-006.md) 等任务里做，各自做的时候同步进契约；本任务只管现有的端点。页面放在哪、与身份服务怎么接是 [S1-IDP-032](S1-IDP-032.md) 的设计，结论要是改了接口的形状，本任务跟着改。

估时与优先级是整理时定的：登录页跑通前后端流程排在新方向的第三步，它要先有这份契约，所以 P0。

## 验收

- [ ] 上面列的账号、连接器、会话与依赖方会话的端点进公开的 OpenAPI 契约（放在 `contracts/identity/v1/`），每个操作标副作用等级；请求不允许多余字段，错误一律是 ErrorDetail，登录失败等防枚举的口径与认证页规格 §1 第 3 条一致
- [ ] 契约测试核对登记的操作与实际端点一致、请求 Schema 与服务端绑定的请求体一致（照 `DirectoryMemberContractTests` 的做法）
- [ ] `contracts/identity/v1/README.md` 加「登录与会话契约」一节：写明哪些端点只能与签发方同源调用、哪些在依赖方一侧，OIDC 协议端点照哪几份标准、平台私有的扩展参数
- [ ] 凭据（密码、验证码、选择令牌、绑定票据）在契约里标成只写，示例里不出现真实格式的令牌
