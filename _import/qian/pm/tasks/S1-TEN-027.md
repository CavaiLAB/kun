## 背景

产品负责人 2026-11-17 裁决（R165）：运营端为已有账号设定凭据的入口统一要求 `qian.tenancy:admin:reset-credential`。运营开户（`POST /api/tenancy/tenants`）与更换管理员（`PUT /api/tenancy/tenants/{id}/admins`）的请求带 `initialPassword` 时，按 R163 会把指定账号的密码设为它并解除外部身份绑定；这两个请求因此在各自的权限点（`tenant:create`、`admin:assign`）之外，还要与重置管理员密码（`POST …/admins/{membershipId}:reset-password`）同一个权限点。

## 验收

- [x] 开户与更换管理员的请求带 `initialPassword` 时，在原有权限点之外再经平台超管旁路判定 `qian.tenancy:admin:reset-credential`。缺这项权限返回 403 `AUTHZ_DENIED`，什么都不改：不设密码、不解除外部身份绑定、不建租户、不换管理员；开户入口在 `ITenantAdministration.PrepareAdministratorAsync` 之前判定。不带 `initialPassword` 的请求不受影响。
- [x] 放行记在平台审计链（`bypass=superadmin`，`payload.permission` 为 `qian.tenancy:admin:reset-credential`），拒绝原因只进结构化日志。
- [x] 运营页面缺这项权限时，在开户与更换管理员的抽屉里给出提示；本机手测宿主有一个缺这项权限的运营身份，租户运营页面 E2E 在真实宿主上覆盖这条提示。
- [x] IT（`TenantAdminTests`）：只有开户或只有指定管理员权限的运营带初始密码被拒，且没有任何改动；两项权限都有时照常；不带初始密码不受影响。
- [x] Tenancy README、`ITenantAdministration` 接口说明与 R165 同步；全量 `dotnet test`、门禁与租户运营页面 E2E 通过。
