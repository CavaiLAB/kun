## 背景

2026-11-26 产品负责人说：「整理 docs 文档目录，移除历史决策」。整理时问他这次动哪些仓库，他选了「匠心和 Kun」，这一项的说明原文是：「两边都整理。Kun 这边移除 docs/decisions（9 份平台决策备忘）和迁移、变更历史这类文档；ADR、PRD 和任务不动。SanYuanAgent 不维护，只改 README 里失效的链接。」又问匠心各篇文档里的裁定编号怎么处理，他选了「一起去掉」：匠心的 `docs/decisions/` 整个删除，各篇不再出现 P 加数字的编号和指向记录的链接。本任务登记本仓库这一边。

引号里是产品负责人的原话。他定的与整理时的读法分开写；读法他没有逐条确认。

### 裁定（产品负责人，2026-11-26）

- D1 移除 `docs/decisions/`：9 份平台决策备忘连同 `evidence/` 目录。9 份是 `authz-identity-revision-wiring.md`、`component-entry-metadata.md`、`feature-flags-write-boundary.md`、`framework-refinement-2026-10.md`、`gateway-native-aot-options.md`、`key-decisions-v0.md`、`runtime-profile-metadata.md`、`system-component-same-version.md`、`tenancy-http-v1-schema-correction.md`。
- D2 移除迁移、变更历史这类文档。具体是哪几篇是整理时的读法，见下面「读法」第 1 条。
- D3 ADR（`docs/adr/`）、PRD（`docs/prd/`）与任务（`pm/tasks/`）不动。这是他选的那一项里写明的。
- D4 匠心的 `docs/decisions/` 整个删除，匠心各篇不再写 P 加数字的编号和指向记录的链接（「一起去掉」）。本仓库跟着改的是指向匠心裁定记录与匠心各篇的链接和说法，见「读法」第 3、4 条。

### 读法

下面都是整理者的读法，产品负责人没有逐条确认。

1. 「迁移、变更历史这类文档」读作这四处：`docs/platform-history.md`（变更日志）、`docs/migration.md`（迁移与归并）、`docs/migration-plan.md`（迁移执行计划）、`docs/platform-migration/`（从参考平台迁移的方案，六篇）。他没有逐篇确认。调研基线 `docs/research/`、路线图 `docs/platform-roadmap.md` 末尾的修订历史这类没有删。
2. 被移除的文件最后一版在提交 `97d521b6df237b092990d7bed8586bda18aebbbc`，固定地址是 `https://github.com/CavaiLAB/kun/blob/97d521b6df237b092990d7bed8586bda18aebbbc/<路径>`。「ADR、PRD 和任务不动」读作原文不改写：这三类与根 `CHANGELOG.md` 里指向被移除文件的链接，只把目标换成固定地址，链接文字与别的字不动，反引号里的路径也不动。
3. 现行文档（README、`AGENTS.md`、`CONTRIBUTING.md`，`docs/` 下其余各篇，各目录里的 README）去掉指向被移除文件的引用，或者把句子改成不靠那篇文档也站得住；需要备忘里的结论才说得通的，把结论用一两句写在原地，不添新的说法。代码与配置只动注释。`docs/platform-overview.md` 与 `docs/_meta.json` 照实去掉对应的条目。
4. 匠心删除决策记录以后：ADR、PRD 与任务里指向匠心 `blob/main/docs/decisions/` 的链接，只把目标换成匠心删除之前的提交 `c7b32a4dea2d1455fd2b9835e1cc0848c9d036c2`；现行文档不再引用匠心的裁定记录，也不再写 P 加数字的编号，本仓库有对应决策任务的改引任务与 D 编号，没有的直接写「产品负责人某日定」的结论。匠心各篇按阅读顺序重新编号，指向旧文件名的链接改成新文件名，节锚点保留；已经带提交号的旧地址不动。

### 没有出入的与没有定的

- 文档站（`website/`）里还有引用被移除文档的地方（首页「最新动态」在构建时读变更日志、指向迁移方案与变更日志的站内链接、站点说明里的几句），以及指向匠心裁定记录的链接，本任务没有改。文档门禁检查站点页面的链接，改好之前报这几处断链；站点构建读变更日志的那一处同样要改。
- 任务的 `refs` 里有指向被移除文件的条目，`python3 scripts/pm.py validate` 要求 refs 指向存在的文件。怎么处理没有定。
- README「已定」里 2026-11-24 一条原来写「影响多个框架的决策记录记在平台总览仓库的 `docs/decisions/`」（[S1-DEC-038](S1-DEC-038.md) D41）。匠心删除决策记录以后这半句不再成立，删掉了，留下「本仓库自己的决定登记成决策任务」；以后平台级的决定记在哪里，没有定。
- 现行文档与代码注释里写的「R 加数字」裁决编号，多数记在被移除的 `key-decisions-v0.md` 里。编号原样保留，原文按上面的固定地址查；以后要不要把它们改写成结论或任务引用，没有定。
- 冻结的契约 `contracts/v0` 没有动，没有改代码的行为，看板上没有新建实现任务。
