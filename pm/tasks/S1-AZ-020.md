## 背景

自 [S1-AZ-005](S1-AZ-005.md) 拆出，是[契约草案](../../docs/prd/specs/authz-remote-interface.md)第 13.1 节四个里的第一个。原任务背景里的四个端点归这里：`POST /api/authz/check`、`/batch-check`、`GET /api/authz/me/allowed-actions`、`POST /api/authz/explain`。原任务的六条验收里没有与它们对应的，下面的验收是照契约草案与 [S1-DEC-045](S1-DEC-045.md) 的裁定新写的。优先级沿用原任务的 P0；它依赖的契约定稿（[S1-AZ-011](S1-AZ-011.md)）因此也标了 P0。排期没有问过（[S1-DEC-048](S1-DEC-048.md) 问题 4）。

这是「本人问自己」的接法：浏览器带着登录会话经网关来问，问的只能是调用方自己。问出来的是预判，只用来决定界面上显示什么，不是执行的依据。S1-DEC-045 里落在本任务上的：

- D1：这一种接法先做。
- D4：界面用的结果可以缓存，最长多久是平台的一项配置，缺省 3 秒，量出来撑不住再放宽。
- D5：界面为了决定显示什么而问的，不逐条留审计，只计数。

形状以 [S1-AZ-011](S1-AZ-011.md) 定稿的契约为准。S1-AZ-005 的进度日志里登记过给这几个端点的接口与口径，开工前先读，要点是：解释建在 `IAuthzService.ExplainDetailedAsync` 上，响应照需求文档 7.5 节展平；别人的角色不能当公开信息返回。

持有授权管理权限的人解释别人，随管理端点做，在 [S1-AZ-021](S1-AZ-021.md)。登记过的系统带着请求体里的主体来做预判是代问，在 [S1-AZ-013](S1-AZ-013.md)；`check` 与 `batch-check` 两个端点由两个任务里先做的那一个建起来。

## 验收

- [ ] IT：四个端点经网关可调。主体与租户只取自已认证的请求，请求体里写不了别的主体；带委托链的与智能体主体照现有端点拒绝；授权组件没有挂载时回 404
- [ ] IT：预判多条的结果与输入同序、条数相同；超过上限直接拒绝，不截断；请求体封闭，不认识的字段回 400
- [ ] IT：解释只解释自己：放行时带出命中的角色与授权记录，拒绝时带出缺少的权限点；只缺二次验证或终端证明的拒绝，原因照现行的两个原因码
- [ ] IT（D5）：这几个端点不逐条写决策审计；按调用方、按结果计数的指标可见
- [ ] IT（D4）：响应带可缓存的时长与授权修订号，现有的 `GET /api/authz/me/permissions` 同样加上；时长的上限是配置，缺省 3 秒，响应里给的不超过它。这个时长是给客户端的，服务端自己不按它缓存：授予或撤销以后再问，结果即反映变更
- [ ] IT：响应不被 HTTP 层缓存；带着登录会话的 POST 没有防伪的请求头时被拒，照登录组件现行的要求
