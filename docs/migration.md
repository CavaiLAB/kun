# 迁移与归并

> 状态：规划稿（2026-11-17）。依据是合并蓝图：`idadawn/qian` 主干上的 `docs/adr/ADR-023-kun-qian-merge-blueprint.md`，2026-11-17 接受，裁定记在同一仓库的 `pm/tasks/S1-DEC-036.md`（D1–D14）。本文是它的摘要，并记下迁到本仓库带来的修订。数字取自 2026-11-17 两个原仓库的主干。
>
> 迁移已于 2026-11-17 启动。分几批、每批做到什么算完，见[迁移执行计划](migration-plan.md)。

首个合并版的 beta 从 CavaiLAB 的 GitHub Packages 还原。稳定版内核档从 nuget.org 还原，平台档从 CavaiLAB 的公开 GitHub Packages 还原，组织包关联 `CavaiLAB/kun`。下文记录 2026-11-17 的规划。升级时可按已安装的包名查找该版本的目标包与包源。[NuGet 包迁移指南](guides/package-migration.md)

## 1 两个来源

| | 原 Kun | 原 Qian 的后端 |
|---|---|---|
| 仓库 | `idadawn/kun` | `idadawn/qian` |
| 是什么 | .NET 10 云原生微服务框架 | 建在 Kun 上的多租户平台 |
| 规模 | 35 个模块，约 2.4 万行 | 56 个包项目，约 6.4 万行；87 个测试项目 |
| 版本 | 日历版本 | 语义化版本，各包同一版本号 |
| 发布位置 | nuget.org | GitHub Packages |

两边合计 91 个包，合并之后是 84 个：内核档 40 个，平台档 44 个。

此前 Qian 精确钉住 Kun 的版本，Kun 每修一处，Qian 就要跟着升一次版本。合并之后，改动和修复在同一个 PR 里过 CI。

## 3 分几步

蓝图把归并分成五个阶段，每一步结束时两边的测试都在同一条流水线上通过，出了问题知道是哪一步引入的。这里的阶段是蓝图内部的编号，不是平台路线的阶段。

| 蓝图的阶段 | 做什么 | 完成的标志 |
|---|---|---|
| 0 蓝图确认 | 蓝图转为已接受；回写受影响的决策记录与两个原仓库的代理入口说明 | 2026-11-17 已完成；原 Kun 仓库的代理入口说明还没有回写 |
| 1 冻结与导入 | 开着的 PR 全部合入或关闭；带着历史把两边的代码导入同一个仓库。这一步不改任何包名 | 导入完成，原仓库只读 |
| 2 构建并轨 | 一个解决方案；原来的包引用改成项目引用；中央包版本取高的一边；依赖门禁改成显式的档位表；CI 并轨。仍不改包名 | 两边全部测试与门禁在一条流水线上通过 |
| 3 按域归并与改名 | 一个域一批，自底向上：错误模型与运行时基础 → 租户上下文与数据 → 事件与审计 → 安全、身份、网关 → 权限 → 配置、存储与文件、测试支持 → 只在原 Qian 的平台组件及宿主、工具、样例。最后一批是前端更名 | 每一批：这个域的每个职责只剩一套公共 API，归档的类型移出解决方案，全量测试通过 |
| 4 首个合并版 | 按日历版本发版；旧的 `Qian.*` 包标为弃用并指向新包名 | 包发布成功 |

两条要点：

- 改名之前先改门禁。现在的依赖门禁按包名前缀判定，包名一改就会不声不响地失效，所以要先换成显式的档位表，并带自测。
- 同一时间一个域只有一个归并批次，功能开发避开正在归并的域。

## 4 名字：哪些改，哪些不改

| 类别 | 内容 | 处理 |
|---|---|---|
| 代码层 | .NET 包名、命名空间、类型名里的 `Qian`、分析器诊断号、构建属性 | 跟着改成 Kun |
| 运行期与生态的字面 | 组件 id 前缀 `qian.`；数据库里的 schema 名；Cookie 名、交换机名、缓存键前缀；契约里的标识与扩展键；清单与配置的文件名（`.qian-plugin/plugin.json`、`qian.profile.yml`、`qian.patch.yml`） | 不改，与包名脱钩 |
| 命令行与导入名 | `qian` 命令行、`@qian/*` 的导入名 | 本次不改 |
| 前端 | yue 的全部包名、目录、样式变量前缀、测试标识、脚本名 | 改名为 qian |

第二类不改，是因为它们已经落库、上线或冻结：改数据库的 schema 名要迁移数据，改 Cookie 名会让在线会话全部失效，改契约标识等于发一个新的主版本，而这些改动不带来任何功能。它们今后只是历史字面，不再表示产品名。

## 5 对现有使用方的影响

首个合并版对原 Kun 包的现有使用方是一次破坏性升级：内置错误码改名、错误类型的形状变了；租户号只收 Guid、没有缺省回落；网关由可执行程序变成库；消息队列的交换机、路由键与消息体改用原 Qian 的现值；有几个包名换了实现；八个包名停发。旧版本留在包源上不动。

用源码引用 Kun 的下游，在归并开始之前先钉住合并前的最后一个 Kun 版本（已定）。

## 7 旧地址

`CavaiLAB/kun` 这个地址在 2026-10 Kun 迁到 `idadawn/kun` 之后一直跳转过去。本仓库建立之后跳转失效。原 Kun 的代码已带历史导入本仓库，现在在仓库根（导入时先落在过渡目录，B2 提到了根上），版本标签也带了过来，指向相同的提交。按提交或版本标签取 Kun 源码的下游可以继续用 `idadawn/kun`：它冻结后归档为只读，仍可读取与克隆。
