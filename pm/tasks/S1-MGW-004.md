## 背景

2026-11-26 产品负责人说要设计标准的接口，用来对接后面的模型推理服务，只提供一套（平台级裁定 P83，本仓库登记在 [S1-DEC-043](S1-DEC-043.md) D5）。[ADR-015](../../docs/adr/ADR-015-model-gateway.md) 第 9 节把「标准接口的形状」记为没有定。平台总览的[总体架构](https://github.com/CavaiLAB/jiangxin/blob/main/docs/02-architecture.md)第 2.2 节有一份提纲（提议），把接口分成调用、接入、管理三个面。

本任务把提纲写成一份可以拿给产品负责人裁定的契约草案：每个面是什么形状，两种形态与两个版本各装什么，和 ADR-015 及 [S1-MGW-001](S1-MGW-001.md) 至 [S1-MGW-003](S1-MGW-003.md) 的出入，哪些问题要他定。

只出文档：不写实现，不改 ADR 与需求文档的原文，不动冻结的契约，不改现有任务的内容。草案通篇是提议；要裁定的问题由 [S1-DEC-044](S1-DEC-044.md) 跟踪，裁定之前照草案开工的任务都不建。

## 验收

- [x] 草案入库，标「提议」，分清已定、读法、提议与没有定
- [x] 写清现状：已有哪些名字与结构，和三个面的提纲哪里对得上、哪里要改；说现状时标「已有」或「规划」
- [x] 调用面：端点清单、认证、逻辑模型名的解析、错误与限流的语义、流式
- [x] 接入面：适配要实现的 .NET 接口与数据结构、清单里的声明、凭据的引用方式；带推理的集群与第三方模型 API 两个适配的轮廓
- [x] 管理面：管理端要用的接口与对应的权限点
- [x] 一张表写清两种形态各装什么，多租户与单租户各差在哪
- [x] 与 ADR-015、S1-MGW-001 至 003 的出入逐条列出，给出建议的任务清单
- [x] 要产品负责人裁定的问题单列，每个有选项、影响与建议，登记为 S1-DEC-044
- [x] ADR-015 末尾追加带日期的小节指向草案，标「提议」，原文不改
- [x] `python3 scripts/check_docs.py` 与 `python3 scripts/pm.py validate` 通过
