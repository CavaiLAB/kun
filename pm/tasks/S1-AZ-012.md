## 背景

[契约草案](../../docs/prd/specs/authz-remote-interface.md)第 13.2 节第 2 项。别的系统真要执行受保护的操作之前问的那一次，是现有执行端口的远程入口：判定、比对身份修订、写决策审计一起做，放行只可能来自现有的求值器。

[S1-DEC-045](S1-DEC-045.md) 里定了的、落在本任务上的：

- D4：这一次每次都问，不缓存。这是硬的一条，不随配置变。
- D5：这一次留审计，拒绝必记，放行按现有的采样配置。条件：高风险的权限点放行也每条都记，不参加采样。「高风险」读作风险等级是 `high` 或 `critical`，是整理时的读法。
- D6、D7：标了要人确认的能力，不算人本人的调用不放行。用哪个原因码表达、怎么按权限点反查能力上的标记，是提议，以定稿的契约为准。别的系统替人来问时怎样算人本人，由登记与本人的令牌决定，那一半在 [S1-AZ-013](S1-AZ-013.md)。按标记回答这一条在别的系统身上用得上，要等 [S1-AZ-016](S1-AZ-016.md) 把它的能力装进平台；本任务的用例拿平台宿主里已有组件登记的能力来验，不等它。

端点、字段与原因码的形状以 [S1-AZ-011](S1-AZ-011.md) 定稿的契约为准。被判定的主体写在请求体里、核验本人的令牌在 S1-AZ-013；本任务先做调用方问自己这一种，两个任务合起来才给别的系统用。

不在本任务里的一样：核验平台转调用时给的凭据。产品负责人 2026-11-26 定（[S1-DEC-048](S1-DEC-048.md) D1）：现在先建等人输入的任务与能力执行入口的契约的任务，只出契约；转调用的执行器等契约定了再建。契约的任务是 [S1-RT-041](S1-RT-041.md)，执行器的任务现在还没有。凭据的格式与签发随执行器一起等，是整理时的读法。本任务先让带着这种凭据的请求一律得到拒绝，不放行。

## 验收

- [ ] IT：端点经网关可调，只收有调用资格的服务主体；一次判一个或几个权限点，全部放行才算放行；每个权限点一条结果、一个判定编号、一条决策审计，同一次请求的几条用请求编号串起来
- [ ] IT（D4）：响应里可缓存的时长恒为 0；授权收回以后下一次判定即拒绝，改任何配置都不会让它缓存
- [ ] IT（D5）：拒绝必记；放行按 `decisionLogSampling` 采样；风险等级是 `high` 或 `critical` 的权限点，采样比例调到 0 时放行照样每条都记；要记的放行写不进审计时变成拒绝。进程内的三处执行点是否一并这样处理，在日志里写明结论与理由
- [ ] IT：审计里看得到执行点是谁（调用方的客户端 id 与组件 id）、请求编号、主体是怎么证明的、算不算人本人、命中的能力标记；入口这个维度有一个远程的取值；审计里不存主体令牌
- [ ] IT（D6、D7）：按调用方那个组件登记的能力反查标记，不靠调用方报。要人确认的能力，不算人本人的调用得到拒绝，原因是要人确认；「仅限人工」只拦智能体主体，不拦服务；命中几项取最严的；请求里报的能力编号只进审计，不能让结果变松
- [ ] IT：调用方越界的问法是一次拒绝，照常记审计：用了别的组件名下的权限点，报的能力对不上。请求体封闭，不认识的字段回 400；超过上限直接拒绝，不截断
- [ ] IT：带着平台转调用凭据的请求一律拒绝，并有用例守住；核验凭据不在本任务的验收里（见背景）
- [ ] IT：审计组件不在、审计写不成时的回答与进程内的执行端口一致；写不成的三个原因（`audit_unavailable`、`decision_log_failed`、`decision_log_invalid`）在接入说明里写明是「判不了」，不是「没权限」
