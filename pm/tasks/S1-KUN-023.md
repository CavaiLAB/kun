## 背景

合并阶段 3（S1-KUN-021）的第 1 批，迁移执行计划（仓库根 `docs/migration-plan.md` 第 4 节）的 B4，对应合并蓝图 ADR-023 D23.9 的第一张表「运行时基础与错误模型」。阶段 3 自底向上，这一批最先做：后面六批都建在它统一出来的错误模型、组件运行时与组件开发包上。命名照 D23.8，档位照 D23.7。

表外三件事：

- 蓝图把归档 Kun.Infrastructure 列在这张表里，前置是数据域先摘掉旧仓储与规约求值器。主干上引用它的是 Kun.EntityFrameworkCore（`EfRepository.cs`、`SpecificationEvaluator.cs`）、AOT 冒烟宿主与门禁样例 `bannedapi/LegacyRepository`，这一批做不了，前置与归档都放在 B5（S1-KUN-024）。
- Kun.AspNetCore 的权限扩展（`Kun.AspNetCore.Authorization` 下的 `RequireKunPermission`）要去的 Kun.Authorization.AspNetCore 到 B8 才有，留到 B8 与 `RequireQianPermission` 并成一个（S1-KUN-027）；这一批只归档异常处理器。
- 测试、工具随域：过渡目录 `_import/qian/tests/` 下的 Qian.Runtime.Errors.Tests、Qian.Runtime.Tests、Qian.Plugin.Sdk.Tests，`_import/qian/tools/Qian.Plugin.Tool`（组件清单工具）；仓库根 `tests/` 下的 Kun.Core.Tests、Kun.Mediator.Tests、Kun.Validation.Tests、Kun.AspNetCore.Tests、Kun.Caching.Tests、Kun.Observability.Tests。过渡目录里随这一批搬出的 .NET 项目共 10 个（6 个包、3 个测试、1 个工具）。门禁样例（`_import/qian/tests/gates/` 下）不随这一批搬，原地跟着换包名、保持能编过，整组归 B10（S1-KUN-029）。

破坏性变更随 PR 记：本批每个 PR 的破坏性变更写进仓库根 `CHANGELOG.md` 的 `[Unreleased]`。理由是发版脚本 `scripts/release.sh` 第 4 段把 `[Unreleased]` 变成版本段，首个合并版的版本说明从这里来（S1-KUN-022）。

- 档位按依赖图复核（仓库根 `scripts/check_deps.py`，项目文件里的 `KunTier` / `KunRole`）：
  - 开发包拆开的做法已定。依赖门禁有 4 条规则 K 例外在 Qian.Plugin.Sdk 上，`Until` 都是 B4。拆后去掉 3 条：→ Qian.Authz.Abstractions、→ Qian.Data.Abstractions、→ Qian.Surfaces.Abstractions，命令管道、`CommandDataSession` 与钩子能力移进 Kun.Plugin.Sdk.Commands。→ Qian.Identity.Abstractions 那条这一批去不掉：原生审计（内核档，B6 换包名为 Kun.Audit.Postgres）要登记审计命令策略、读 `CommandInvocation`，而 `CommandInvocation.Principal` 的类型在 Qian.Identity.Abstractions。这条例外随声明一半改记在 Kun.Plugin.Sdk 上，`Until` 改为 B7，Principal 下沉安全域之后去掉（S1-KUN-026）。另一个办法是把原生审计改记平台档，与 D23.9（Kun.Audit.Postgres 记内核档）不符，不取。这一批之后依赖门禁的例外剩 8 条。

  - 升版本：同一个组件被先后几个 PR 改到，每个 PR 各升一次，不看前一次升的版本部署过没有（何时部署另定，可能落在任意两次合入之间）。升哪一位照 R167 采纳的做法：只改说明文字升修订号；对外行为不变的改动（清单里的入口类型与程序集名、契约文件里的 Schema 键）与兼容的增加（加权限点、可选字段）升次版本；对外行为变了、不兼容（线上契约、权限点、配置 Schema）升主版本。

- 会扫到全仓的换包名用一个可重放的脚本做，一个 PR 一步，人工改动单独提交；主干动了就在新主干上重跑脚本、再摘人工提交。
