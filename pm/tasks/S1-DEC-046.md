## 背景

2026-11-26 产品负责人说：「整理 docs 文档目录，移除历史决策」。整理时问他这次动哪些仓库，他选了「匠心和 Kun」，这一项的说明原文是：「两边都整理。Kun 这边移除 docs/decisions（9 份平台决策备忘）和迁移、变更历史这类文档；ADR、PRD 和任务不动。SanYuanAgent 不维护，只改 README 里失效的链接。」又问匠心各篇文档里的裁定编号怎么处理，他选了「一起去掉」：匠心的 `docs/decisions/` 整个删除，各篇不再出现 P 加数字的编号和指向记录的链接。本任务登记本仓库这一边。

引号里是产品负责人的原话。他定的与整理时的读法分开写；读法他没有逐条确认。

### 裁定（产品负责人，2026-11-26）

- D1 移除 `docs/decisions/`：9 份平台决策备忘连同 `evidence/` 目录。9 份是 `authz-identity-revision-wiring.md`、`component-entry-metadata.md`、`feature-flags-write-boundary.md`、`framework-refinement-2026-10.md`、`gateway-native-aot-options.md`、`key-decisions-v0.md`、`runtime-profile-metadata.md`、`system-component-same-version.md`、`tenancy-http-v1-schema-correction.md`。
- D2 移除迁移、变更历史这类文档。具体是哪几篇是整理时的读法，见下面「读法」第 1 条。
- D3 ADR（`docs/adr/`）、PRD（`docs/prd/`）与任务（`pm/tasks/`）不动。这是他选的那一项里写明的。
- D4 匠心的 `docs/decisions/` 整个删除，匠心各篇不再写 P 加数字的编号和指向记录的链接（「一起去掉」）。本仓库跟着改的是指向匠心裁定记录与匠心各篇的链接和说法，见「读法」第 3、4 条。

### 读法

> 2026-11-27 补记：这一节的读法列在成批的甲批「读法与做法，都认可。」里，产品负责人 2026-11-27 答「甲认可」（登记在 [S1-DEC-049](S1-DEC-049.md)），转成已定。

下面都是整理者的读法，产品负责人没有逐条确认。

1. 「迁移、变更历史这类文档」读作这四处：`docs/platform-history.md`（变更日志）、`docs/migration.md`（迁移与归并）、`docs/migration-plan.md`（迁移执行计划）、`docs/platform-migration/`（从参考平台迁移的方案，六篇）。他没有逐篇确认。调研基线 `docs/research/`、路线图 `docs/platform-roadmap.md` 末尾的修订历史这类没有删。
2. 被移除的文件最后一版在提交 `97d521b6df237b092990d7bed8586bda18aebbbc`，固定地址是 `https://github.com/CavaiLAB/kun/blob/97d521b6df237b092990d7bed8586bda18aebbbc/<路径>`。「ADR、PRD 和任务不动」读作原文不改写：这三类与根 `CHANGELOG.md` 里指向被移除文件的链接，只把目标换成固定地址，链接文字与别的字不动，反引号里的路径也不动。
3. 现行文档（README、`AGENTS.md`、`CONTRIBUTING.md`，`docs/` 下其余各篇，各目录里的 README）去掉指向被移除文件的引用，或者把句子改成不靠那篇文档也站得住；需要备忘里的结论才说得通的，把结论用一两句写在原地，不添新的说法。代码与配置只动注释。`docs/platform-overview.md` 与 `docs/_meta.json` 照实去掉对应的条目。
4. 匠心删除决策记录以后：ADR、PRD 与任务里指向匠心 `blob/main/docs/decisions/` 的链接，只把目标换成匠心删除之前的提交 `c7b32a4dea2d1455fd2b9835e1cc0848c9d036c2`；现行文档不再引用匠心的裁定记录，也不再写 P 加数字的编号，本仓库有对应决策任务的改引任务与 D 编号，没有的直接写明产品负责人哪天定了什么。匠心各篇按阅读顺序重新编号，指向旧文件名的链接改成新文件名，节锚点保留；已经带提交号的旧地址不动。
5. 任务 frontmatter 的 `refs` 也按只换链接目标的规矩处理：指向被移除文件的条目换成上面的固定地址，`#` 之后的小节号留着，别的字段与正文不动。`scripts/pm.py` 校验 refs 时，只对 `https://github.com/CavaiLAB/kun/blob/<40 位提交号>/<路径>` 这一种地址不查存在，看板照这个地址链过去；别的地址、别的仓库照旧报错，别的校验规则不变。集群看板每换一个提交就用该提交自己的 `scripts/pm.py` 生成（`deploy/pm-board/README.md`），合入后看板随之更新。
6. 文档站（`website/`）跟着改到能构建、门禁能过为止，只做与这次移除直接有关的改动：首页「最新动态」原来在构建时读 `docs/platform-history.md`，改读仓库根 `CHANGELOG.md` 里已发布的版本段，链接到「Kun 版本记录」`/sdk/kun/releases/`；首页、开始页与指南页去掉指向迁移方案与变更日志的入口；产品族、宿主与框架、前端 SDK、网站 README 与版本矩阵脚本去掉指向匠心裁定记录的链接，事实照写。这部分改动记在文档站任务 S1-DOCS-010 名下（提交与标注都带它的任务号）。`docs/prd/specs/docs-site.md` 是记录类，照记录类的规矩只加带日期的标注、原文不改：§2a.1 前一条（S1-DOCS-010），§2 第 7 部分一行的「变更日志」前一条（本任务），修订历史各记一行。「设计与路线」随之少了决策 9 页、迁移 6 页、变更日志 1 页。

### 没有出入的与没有定的

- 文档站的说明里还有三句把「变更日志」算在 `/design/` 镜像里：`website/README.md` 七个部分的表里第 7 部分一行与「设计文档、规格与变更日志只改仓库 `docs/`」一条，`website/AGENTS.md` 来源表的第一行。不是链接，门禁不报，本任务没改；由本任务还是文档站任务 S1-DOCS-010 来改，没有定。
- README「已定」里 2026-11-24 一条原来有半句说，影响多个框架的决策记录记在平台总览仓库的 `docs/decisions/`（[S1-DEC-038](S1-DEC-038.md) D41）。匠心删除决策记录以后这半句不再成立，删掉了；同一句里本仓库自己的决定登记成决策任务的说法留着。以后平台级的决定记在哪里，没有定。
- 现行文档与代码注释里写的 R 加数字的裁决编号，多数记在被移除的 `key-decisions-v0.md` 里。编号原样保留，原文按上面的固定地址查；以后要不要把它们改写成结论或任务引用，没有定。
- 被移除的文档里有三条现行的约定，结论只写在那里：验收条目要求的用例要有区分度，把被测分支删掉或反转用例必须失败（R112，2026-10-17 起适用于全部验收复核）；新写的文档不写未修复的安全问题的细节、不写私有仓库的内部实现（原迁移执行计划第 3 节）；原 Kun 的代码与版本标签已带历史导入本仓库，按提交或标签取源码的下游可以继续用只读的旧仓库（原《迁移与归并》第 7 节）。要不要把它们并进现行文档、并到哪一篇，没有定。
- 冻结的契约 `contracts/v0` 没有动。除了 `scripts/pm.py` 对固定地址 refs 的处理（读法第 5 条），没有改代码的行为；看板上没有新建实现任务。
- 2026-11-27 补记（[S1-DEC-049](S1-DEC-049.md)）：上面没有定的四件，有两件有了答复。以后平台级的决定记在哪里：原表第 38 条的建议是「裁定照旧记在私有台账，公开文档只写结论；匠心开工时在匠心仓库里建一个和 Kun 一样的任务看板。」（照建议定）；本仓库的决定照旧登记成决策任务，是整理时的做法。三条约定搬进本仓库的贡献说明，列在成批的丙批里，按提议推进，还没有搬，记在 S1-DEC-049 的「后续」。R 加数字的编号要不要改写，仍没有定；文档站说明里那三句由谁改，这次没有答到，仍没有定。上面没有列的一件也在丙批里：另有六篇同类的文档照同一口径删掉，按提议推进，还没有删。
