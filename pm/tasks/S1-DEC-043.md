## 背景

2026-11-26 产品负责人对平台说了一批新的方向，原文记在 `CavaiLAB/jiangxin` 的 [2026-11-26 平台级裁定](https://github.com/CavaiLAB/jiangxin/blob/main/docs/decisions/2026-11-26-platform.md)（P78–P86）。其中几条与本仓库已接受的决策记录有关，或者要在本仓库记一笔。2026-11-25 的 P77（前端框架 Qian 的仓库归档，记在那边的 [2026-11-25 平台级裁定](https://github.com/CavaiLAB/jiangxin/blob/main/docs/decisions/2026-11-25-platform.md)）当时没有回写到本仓库，这次一起补上。本任务照 [S1-DEC-041](S1-DEC-041.md)、[S1-DEC-042](S1-DEC-042.md) 的写法登记它们，括号里是平台级裁定的编号。ADR 的原文不改：对应的 ADR 末尾追加带日期的小节，受影响的条目前加标注；没有出入的只在文首记一笔。

引号里是产品负责人的原话。方括号里是整理时替换的说法：他这次说把平台此前的一条理念全都移除（D3），照这句话，本任务不写那条理念的名字，原话里出现的地方换成「［此前的理念名］」。他的话里有几处要靠读法才能动手，读法单列在下面，都是整理者的读法，产品负责人没有逐句确认。

### 裁定（产品负责人，2026-11-25 与 2026-11-26）

- D1 前端框架 Qian 的仓库归档（P77，2026-11-25）。问的是「Qian 的仓库现在归档吗？」，两个选项是「归档，包留着」「先不归档」，答「归档，包留着」。仓库归档，只读；已发布的包留着，继续可以安装；Qian 不再发新版，要发先取消归档。2026-11-26 他说的「前端 Qian 归档」是同一件事。与本仓库有关的：[ADR-013](../../docs/adr/ADR-013-frontend-framework.md) 把它定为前端框架，§6 里后面各阶段还有分给它的内容；[ADR-023](../../docs/adr/ADR-023-kun-qian-merge-blueprint.md) D23.6 的定位里写「前端使用 qian 组件库」；[ADR-021](../../docs/adr/ADR-021-product-family-structure.md)、[ADR-022](../../docs/adr/ADR-022-rspress-unified-component-docs.md) 把它算在产品族与文档站里。
- D2 现在只剩两个项目：匠心与 Kun；SanYuanAgent 保留，先不维护（P78）。原话「经过一段考虑，前端 Qian 归档，SanyuanAgent 保留先不维护，现在只剩下  Jiangxin 和 Kun」。与本仓库有关的：ADR-021 的产品族；[ADR-016](../../docs/adr/ADR-016-agent-boundary.md) 文首此前标的「SanYuanAgent 暂缓开发，现在使用 DSH」（[S1-DEC-038](S1-DEC-038.md) D45）。Kun 自己的定位不变。
- D3 平台此前的那条理念全都移除，平台只按一句话描述（P79）。原话「把之前的理念［此前的理念名］全都移除。」平台以后只按这一句描述：匠心工业智能体平台，企业级的 AI 原生平台。人用自然语言说清要什么，智能体把它落成可运行的系统；系统上线后在人的反馈里继续改进。本仓库里只有 [README](../../README.md)「定位」一节有一句拿那条理念讲 Kun 的位置，删掉；决策记录与需求文档里没有写到它。
- D4 Kun 增加单独的网站（P82）。原话「Kun 增加单独网站增加使用文档和说明。方便后续其他人使用，增加给大模型使用的类似 llm.txt 这种文档。方便进行调用。」与本仓库有关的：ADR-022 D22.1 的「唯一文档与演示体系」，ADR-013 D13.18 与 ADR-021 D21.2 第 2 点的文档站。
- D5 企业级框架分两种，多租户与单租户两个版本，统一由管理端管理，尽量做成插件，模型服务留标准的接口、只提供一套（P83）。原话「企业级框架分为两种 1.K8s集群，包括模型推理服务， GPU Stack 等 2.不包括直接接入第三方模型服务，通过 API 方式，可以参考框架。 3.提供多租户和单租户两个版本。 但是不管哪种方式 统一由管理端进行管理。以上尽量使用插件的形式进行实现。所以你要设计一些标准的接口，方便我对接后面的模型推理服务，因为我只想提供一套。」与本仓库有关的：[ADR-015](../../docs/adr/ADR-015-model-gateway.md)（模型服务网关）与 [ADR-017](../../docs/adr/ADR-017-deployment.md)（部署）。没有出入，是加上的内容。
- D6 代码要符合 ISO 等国际相关标准（P84）。原话「代码要符合 ISO 等国际相关标准。」本仓库没有讲代码对着哪些标准的决策记录，这次只在本任务里记一笔。
- D7 平台上不论做什么系统，权限都走这一套，在 Kun 上做好（P86）。原话「另外，这个企业级平台后续不论做什么系统，权限都是要走这一套的，所以要在  Kun 框架上做好这部分。」与 [ADR-006](../../docs/adr/ADR-006-authorization-model.md) D6.8「鉴权唯一入口」同向，没有出入；范围说到了平台上做的所有系统。

### 读法

下面都是整理者的读法，产品负责人没有逐句确认。

- D2：「SanyuanAgent 保留先不维护」读作仓库留着、不归档，代码和文档停在现在的样子。「只剩下 Jiangxin 和 Kun」读作在用、在维护的项目是这两个；四个仓库都还在。Agent 运行时用 DSH，没有变。
- D4：本仓库已有文档站，构建时已经产出 llms.txt（[S1-DOCS-003](S1-DOCS-003.md)）。它只部署在内部，Kun 的文档和前端框架的组件页放在一起。「增加单独网站」读作把它做成 Kun 自己的、别人打得开的站，补上使用文档。「类似 llm.txt 这种文档」读作 llms.txt 这一类给大模型读的入口。
- D5：两种形态按带不带模型推理分。第二种的原话「不包括直接接入第三方模型服务，通过 API 方式」读作：不包括模型推理，通过 API 直接接入第三方的模型服务。「可以参考框架」读作可以参考现成的开源框架，没有说是哪个。「提供多租户和单租户两个版本」读作另一件事，重申平台级裁定 P33。这次说的两种形态，与企业版、单机版（S1-DEC-041 D2、D3）、与多租户和单租户，读作三条不同的线。「统一由管理端进行管理」读作两种形态、两个版本用同一个管理端，模型服务也在里面管；管理端在匠心（S1-DEC-041 D5、D6）。「尽量使用插件的形式」读作模型推理的接入、形态之间与版本之间的差别，尽量做成本仓库的组件，换一个组件就换了形态。「标准的接口……只提供一套」读作模型服务这一块留一个标准的接口，后面接自己的推理服务还是第三方的 API 都接在它上面，上面的产品不用跟着改。
- D6：读作定一份标准对照，配上相应的检查，文档里写明对着哪些标准、各自做到了哪一步；不是去做认证。
- D7：读作平台上做的任何系统判权限只问 Kun，不各做一套；管理端、应用、插件、Agent、DSH 一侧的服务都算。

### 没有出入的与没有定的

- 平台级裁定里另外三条不登记：P80（两种角色移除）、P81（「三个框架」的说法移除，任务与文档重新整理）、P85（文档要写清楚的四件事）讲的是匠心的文档与任务。本仓库的文档里引用「三个框架的分工」的地方、README 其余各节，这次都没有改。
- D1：本仓库的旧外壳、界面包、参考应用的远程模块与文档站还引用 Qian 已发布的包，归档以后照常能装。这些界面以后怎么办，没有定。ADR-013 §6 里 S2 至 S4 分给前端框架的内容怎么对应到匠心一侧，没有定。组件 id 前缀 `qian.`、`qian` 命令行这些运行期字面，现行的决定是当作历史字面保留（ADR-023 D23.18）；前端框架归档以后要不要重看，没有问。
- D2：ADR-016 的边界怎么改写（S1-DEC-038 的 Q5）仍待定。SanYuanAgent 以后怎么接，没有定。
- D4：网站对外放在哪，没有定；现在只部署在内部。站里前端框架的组件页怎么办，没有定。已有的 llms.txt 够不够、还要补什么，没有定。平台文档站在 `CavaiLAB/jiangxin`（S1-DEC-038 D8）没有变；那个站还聚不聚本仓库的文档，是那边的提议，没有定。
- D5：标准接口的形状没有定。第二种形态的数据面要不要也过模型网关，没有定：照 ADR-015 D15.5、D15.10，应用不绕过模型网关直连，租户自带的模型端点只能登记成它的上游。哪几种形态与版本的组合要交付，没有问。组件 `qian.model-gateway` 现在只有配置骨架，[S1-MGW-001](S1-MGW-001.md) 至 [S1-MGW-003](S1-MGW-003.md) 都没有开始；这次没有动它们。
- D6：对着哪些标准，没有定。本仓库现有的构建、测试与发布门禁不变。ADR-005、ADR-006 §7 里等保与商密的待确认项照旧。
- D7：给别的进程、别的语言用的远程授权接口是规划，还没有实现；[S1-AZ-005](S1-AZ-005.md) 没有开始，这次没有动它。先做哪几种接法，没有定。
- 冻结的契约 `contracts/v0` 没有动，看板上没有新建实现任务，没有改代码。
