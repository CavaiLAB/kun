## 背景

合并阶段 3（S1-KUN-021）的收尾，迁移执行计划（仓库根 `docs/migration-plan.md` 第 4 节）的 B13「过渡目录搬空」。七个批次（S1-KUN-023 至 029，即 B4–B10）只管 .NET 内容：项目、门禁样例、链接的共享源文件与 .NET 构建文件，B10 做完，过渡目录 `_import/qian/` 里不再有 .NET 内容。剩下的非 .NET 内容在这一批按合并蓝图 ADR-023 D23.13 第 1 点的目标布局搬到仓库根，或者删掉；全部搬完，导入子目录消失（D23.13 第 2 点，也是 S1-KUN-021 验收的最后一条）。排在 B10 之后、首个合并版（S1-KUN-022，即 B12）之前。前端移出（B11，由前端计划做）删掉的目录不归这一批。

谁在取用这些路径：

- 前端仓库按清单从本仓库复制 5 个文件并按摘要钉住：`contracts/v0` 的 `error-codes.json`、`error-detail.schema.json`、`fixtures/capability-entry.valid.json`，`schemas/v2/ui.schema.json`，`tck/surfaces/cases.json`。来源路径一变，前端仓库的清单要同步改。
- 平台文档站钉本仓库的提交取文档；动 `docs/`、`website/` 的路径与布局之前先核对它的取用约束，合入后升钉。
- 镜像：构建上下文与两份 dockerignore（`deploy/images/aot.Dockerfile.dockerignore`、`jit.Dockerfile.dockerignore`）按过渡目录的路径放行文件。
- 仓库根：`.github/workflows/` 里 11 个文件共 140 行写着 `_import/qian`，`ci.yml` 与区域表 `scripts/ci_changes.py` 按它分区；`scripts/` 下 3 个文件 18 行（区域表与它的两份自测）；`AGENTS.md` 17 行、`README.md` 4 行。过渡目录里 `deploy/` 有 11 个文件 58 行、`scripts/` 有 4 个文件 8 行。
- 发版：过渡目录的 `scripts/dotnet_release.py` 与 `.github/` 下的 `dotnet-release.yml` 副本（前者随 .NET 自测归 B10，后者删）。
- 看板：`pm.py` 按自己所在的位置定根（现在是 `_import/qian/`），任务文件里按过渡目录根写的 `refs` 路径有 1027 条（主干 1165241e 上数，本 PR 合入后是 1073 条）。目标布局与过渡目录同构，整体搬到仓库根之后多数不用改，`pm.py` 的根与撞名的顶层项要核。看板的部署按环境变量 `BOARD_PREFIX`（`scripts/pm.py` 与 `pm/tasks/` 在检出里所在的目录）取内容；文档站的部署发布 `website` 的构建产物（`deploy/docs-site/publish.sh`）。
- 两边顶层有 14 个同名项（D23.13 第 2 点）。`.editorconfig` 与三个 `Directory.*` 构建文件归 B10；其余 10 个（`.github/`、`.gitignore`、`AGENTS.md`、`CLAUDE.md`、`README.md`、`docs/`、`samples/`、`scripts/`、`tests/`、`tools/`）在这一批合并，不能直接叠在一起。

运行期字面不改（D23.10 第二类）：组件 id 前缀 `qian.`、清单与配置文件名（`.qian-plugin/plugin.json`、`qian.profile.yml`、`qian.patch.yml`、`.qian/`）、契约标识 `https://qian.dev/…` 与 `x-qian-*` 扩展键、部署命名空间与镜像标签。搬目录只改路径。

开工前要补的事：

- 执行会话先出方案：盘点表逐项定去处或删掉、搬的顺序、跨仓库改动的时序，复核后再动。
- 前端仓库与平台文档站对这些路径的取用约束：前端仓库按什么路径复制哪几个文件，文档站读哪些目录、钉哪个提交。
- 看板与文档站的部署清单按本仓库的路径取内容（看板按 `BOARD_PREFIX`），改路径要部署一侧同步改。部署一侧不在本仓库，那边的改动由产品负责人批。
- system 级组件的文件夹搬动会不会改变目录摘要（S1-DEC-037）：摘要按整个组件文件夹算（口径同 `scripts/sign-system-revisions.py`），只换上层路径、文件夹里的内容不变时应当不变，要实测核实。会变的话，组件版本与预发环境清库怎么办先定（R167）。
- B11 删掉哪些前端目录以前端计划为准，这一批只处理留下的；B11 还没做完的话，先与前端计划对齐顺序。
- 撞名的 10 个顶层项各怎么合并。

估算 5d（4–7 人日），依据是在主干 1165241e 上量的：

- 非 .NET 文件 1129 个，分在 17 个顶层项里；其中约 30 个是 .NET 的构建文件、共享源文件、按 `Qian.slnf` 工作的脚本与测 .NET 构建和工具的自测，归 B10；B11 删掉的前端目录另算。
- 写着过渡目录路径的地方：仓库根工作流 11 个文件 140 行、脚本 3 个文件 18 行、`AGENTS.md` 与 `README.md` 21 行，过渡目录的部署清单与脚本 15 个文件 66 行；任务文件里的 `refs` 1027 条（本 PR 合入后 1073 条）。
- 跨仓库要跟的有三处：前端仓库的复制清单、平台文档站的取用与钉、部署一侧的看板与文档站清单。
- 分配：盘点与方案 0.5d，看板（`pm.py`、`refs`、部署前缀）1d，文档、文档站与 ADR 1d，契约、Schema、TCK、profile 与组件（含摘要核对）1d，部署清单、脚本、工作流副本、根上的配置与 `ci.yml`、区域表 1d，跨仓库跟进与收尾 0.5d。
