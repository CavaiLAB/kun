## 背景

> 2026-11-27 补记：本任务照 [ADR-024](../../docs/adr/ADR-024-model-entry-no-gateway.md) 改写了。原来的范围是经 Higress 限流（`x-qian-consumer` 作限流桶键、`ai-token-ratelimit`），从响应回流 usage 落计量事件，并写明不自写模型代理。产品负责人 2026-11-26 说到 Higress，原话是「评估一下，不需要就不安装了吧。你觉得有这个必要吗？因为它安装起来还是挺复杂的。」评估是整理者做的，结论是不需要；照他这句话里的条件，平台不装 Higress（ADR-024 D24.4）。计量与限流改由平台自己的模型入口做，模型入口是 ADR-024 的提议，与原来写的不自写模型代理相反。同一天他定了额度的单位用积分，积分系统可以选择启用或不启用，周期可以选择（ADR-024 D24.1 至 D24.3），这三件加进了范围。标题、范围与验收照此改写，依赖里加了 [S1-DEC-044](S1-DEC-044.md)，都是整理时改的，没有问过；估时没有重估。原来的范围与验收在本文件的提交历史里，改了什么记在进度日志里。

> 2026-11-27 补记（《决策表》）：产品负责人 2026-11-27 对《决策表》一次定稿（[S1-DEC-044](S1-DEC-044.md)、[S1-DEC-049](S1-DEC-049.md)，ADR-024 §10）。额度与积分的几项照原表第 14、15 条定了，「用户可以主动选择另一个已获授权且有额度的模型。」是他的原话（D24.9）；S1-DEC-033 的 D6 照原表第 12 条确认。照此：去掉了「开工前要有的答复」，范围与验收写进已定的几项；依赖去掉 S1-DEC-044。都是整理时照答复改的，估时没有重估。

2026-11-11 按 S1-DEC-033 D6 拆分（待产品负责人确认）：上游入 git、租户 consumer 与 OpenAI 兼容面调用移到先行段 S1-MGW-003，原验收 2、3 随之移过去。本任务留计量与限流。

（2026-11-27 补记：上游入 git 与租户 consumer 是经 Higress 的做法，不再做；[S1-MGW-003](S1-MGW-003.md) 改成了模型入口的先行段。D6 的拆法没有变，仍待确认。）

（2026-11-27 补记（《决策表》）：D6 照原表第 12 条确认。）

范围照[契约草案](../../docs/prd/specs/model-service-interface.md)第 6.5、8.3 节写。额度的单位用积分、积分系统可以选择启用或不启用、周期可以选择，这三件已定（D24.1 至 D24.3）。2026-11-27 原表第 14、15 条照建议定了：开关按租户设，关着时用量照记、不拦；周期可选日、周、月，缺省每周一重置；按 token 乘模型系数算，输入输出分开，自建的模型也计；租户管理员设每人的默认额度，多租户版由平台给租户封顶，应用单独一桶；按模型组分桶，用完就拒，不自动换模型，另加每分钟的限流。用户可以主动换另一个已获授权且有额度的模型（D24.9）。DSH 里显示剩余、剩一成时提醒在匠心一侧，平台给剩余与重置时间（草案第 8.1 节的 `GET /me/quota`，提议）。其余照草案写，是提议。模型入口边转边读用量，结束时写一条用量记录，带租户、主体、逻辑模型、输入与输出的 token、积分、用量的来源，投影成 7.11.2 的计量事件（`unit = token`）；流中途断了按已经转出去的量估，标成估的。输入与输出的 token 分别乘模型的系数，折成积分。计数放在共享的存储里，多副本共用。

原来开工前要的答复（用完以后怎么办、分不分桶、要不要每分钟的限流；周期有哪几种、缺省是哪一种；积分怎么折算），2026-11-27 都有了，见上。积分系统关着时积分照不照算，没有定。

## 验收

- [ ] E2E：租户 A 的应用经 OpenAI 兼容面完成一次 chat 与一次 embedding 调用，`meter_events` 出现 `unit = token` 记录，带 `tenant_id` 与主体；用量记录里有这一次的积分与用量的来源
- [ ] E2E：积分系统开着时，一个人本周期的积分用完以后再调，返回 429 `insufficient_quota` 并带重置时间，请求不打到上游；关着时用量照记、不拦。用完以后拒绝、不自动换模型，关着时用量照记、不拦，都已定（原表第 14、15 条）。原验收里超过 `ai-token-ratelimit` 阈值返回 429 的那一半由这一条接替
- [ ] IT：两个副本共用计数，并发调用下扣的积分与用量记录对得上；流中途断开的那一次记成估的
- [ ] IT：按模型组分桶，一个组用完以后另一个组照常；每分钟的限流超了回 429 `rate_limit_exceeded` 并带 `Retry-After`，与积分用尽分得开
- [ ] IT：周期可选日、周、月，缺省每周一重置；租户管理员设的每人默认额度、平台给租户的封顶、应用单独的一桶各自生效
- [ ] IT：调用方查得到自己在各模型组上的剩余积分与重置时间，给 DSH 显示剩余、剩一成时提醒用（原表第 15 条）；接口照草案第 8.1 节的 `GET /me/quota` 写，是提议
