## 背景

合并阶段 3（S1-KUN-021）的第 5 批，迁移执行计划（仓库根 `docs/migration-plan.md` 第 4 节）的 B8，对应合并蓝图 ADR-023 D23.9 第二张表「数据、租户、权限」里的权限部分（数据与租户在 B5）。权限族叫 `Kun.Authorization.Rbac`（D23.19 第 5 点）。命名照 D23.8，档位照 D23.7。

范围在主干 82b3e47e25 上核过。「公共 API」是 `PublicAPI.Shipped.txt` 与 `PublicAPI.Unshipped.txt` 去掉首行 `#nullable enable` 与空行后的行数；「引用方」是直接引用它的项目数，括号里是其中的门禁样例。

| 合并后的包 | 来源与主干上的目录 | 档位 | 公共 API | 引用方 | 归并动作 |
|---|---|---|---|---|---|
| Kun.Authorization | `src/Kun.Authorization` | 内核契约，AOT | 98 | 6 | 端口原样 |
| Kun.Authorization.Rbac.Abstractions | Qian.Authz.Abstractions，`_import/qian/packages/Qian.Authz.Abstractions` | 平台契约 | 351 | 23（8） | 换包名；过滤表达式与判定主体两边各有一份类型，合一 |
| Kun.Authorization.Rbac | Qian.Authz，`_import/qian/packages/Qian.Authz` | 平台提供者 | 51 | 5 | 换包名；引擎不再按类型名字符串挂接中介的内部类 |
| Kun.Authorization.AspNetCore | Qian.Authz.AspNetCore，`_import/qian/packages/Qian.Authz.AspNetCore` | 平台提供者 | 57 | 4 | HTTP 与 gRPC 的强制执行点两边各有一套，留 Qian.Authz.AspNetCore 的；`RequireKunPermission` 与 `RequireQianPermission` 并成一个 |

表外几件事：

- `AddKunAuthorization` 与 `RequireKunPermission` 现在在 Kun.AspNetCore（`src/Kun.AspNetCore/Authorization/KunPermissionExtensions.cs`）。B4 让 Kun.AspNetCore 只留端点映射，这两个权限扩展留到这一批移出 Kun.AspNetCore、搬进 Kun.Authorization.AspNetCore，`RequireKunPermission` 与 `RequireQianPermission` 并成一个；这一批之后 Kun.AspNetCore 只剩端点映射。
- B4 已让 `AuthorizedHandlerRegistration` 与 `AuthorizedHandlerTests` 改用 Kun.Mediator 的正式权限扩展点（S1-KUN-023）。本批核对改名后两处仍使用该扩展点。
- 测试随域：过渡目录 `_import/qian/tests/` 下的 Qian.Authz.Tests、Qian.Authz.Abstractions.Tests。本批搬出 4 个 .NET 项目（3 个包、1 个契约测试）。依赖容器夹具的 Qian.Authz.Tests 原地换名，随 B9 搬（S1-KUN-028）。门禁样例（`_import/qian/tests/gates/` 下）不随这一批搬，原地跟着换包名、保持能编过，整组归 B10（S1-KUN-029）。

破坏性变更随 PR 记：本批每个 PR 的破坏性变更写进仓库根 `CHANGELOG.md` 的 `[Unreleased]`。理由是发版脚本 `scripts/release.sh` 第 4 段把 `[Unreleased]` 变成版本段，首个合并版的版本说明从这里来（S1-KUN-022）。

开工前要补的事：

- 蓝图 §1.2 的未核实事项没有落在这一域的。
- 档位按依赖图复核（仓库根 `scripts/check_deps.py`，项目文件里的 `KunTier` / `KunRole`）：三个 Rbac 包都在平台档；Kun.Mediator 与 Kun.Grpc 依赖的 Kun.Authorization 是内核契约，不变。若 B4 留下了 Qian.Plugin.Sdk → Qian.Authz.Abstractions 那条例外，这一批去掉。
- 平台分析器 QIAN0005（受保护命令的登记入口）按程序集名 `Qian.Authz.Abstractions` 与类型全名 `Qian.Authz.Abstractions.AuthorizedHandlerRegistration` 认出唯一可信的登记桥接；换包名时不跟着改，桥接自己的登记会被当成违规报错。authz 一组 8 个门禁样例都引用 Qian.Authz.Abstractions，跟着改，照旧按预期报错。
- 组件元数据生成器按类型全名识别 `PermissionAttribute`。改名时同步更新，重新导出 qian.authz 的权限声明并逐项核对。
- 边界测试 `PermissionContractTests` 断言权限契约的 4 个项目引用为 Kun.Authorization、Kun.EventBus.Abstractions、Kun.Mediator 与 Kun.Runtime，换包名后照原意改写。
- 对前端有没有影响：`plugins/qian.authz` 的清单写着入口类型与程序集名，随包换；组件 id 不变。改之前先看。
- 组件版本：`_import/qian/plugins/` 下 system 级组件（`policy.tier` 为 system、`runtime.form` 为 module 的非骨架组件，口径同 `scripts/sign-system-revisions.py` 的签名清单）的文件夹里任何文件一改，目录摘要就变：清单里的入口类型与程序集名随包换、README 改一个字都算。按 S1-DEC-037 的裁决（R167），要连带升该组件的版本，版本号继续唯一对应文件夹的内容。这一批碰到的 system 级组件：qian.authz。
  - 升版本：同一个组件被先后几个 PR 改到，每个 PR 各升一次，不看前一次升的版本部署过没有（何时部署另定，可能落在任意两次合入之间）。升哪一位照 R167 采纳的做法：只改说明文字升修订号；对外行为不变的改动（清单里的入口类型与程序集名、契约文件里的 Schema 键）与兼容的增加（加权限点、可选字段）升次版本；对外行为变了、不兼容（线上契约、权限点、配置 Schema）升主版本。
  - 发布的 HTTP 契约会随换包名漂移：组件 Schema 的键取类型程序集限定名的哈希（`Qian.Capabilities.AspNetCore` 的 `AspNetCoreHttpContractSource`），发布契约三份，是 `plugins/qian.registry`、`plugins/qian.tenancy`、`plugins/qian.tenancy.signup` 下的 `contracts/http-v1.openapi.json`。在主干 691eabad 上按键反推，这一批要换的包里没有类型出现在这三份契约里，不会漂；换包名之后仍以 CI 上三处漂移测试（Qian.Registry.Tests、Qian.Sample.Crm.Tests、Qian.Tenancy.Signup.Tests）通过为准，漂了就重新生成并照上面升版本。
- 文档：仓库根 `docs/` 里有 4 个页面写到 Kun.Authorization：`architecture.md`、`design/module-map.md`、`design/whitepaper.md` 与决策记录 `adr/kun/ADR-016-platform-ports.md`。端口原样，`RequireKunPermission` 并名之后看前三个是否跟着改；决策记录是历史文字，不改。

估算 5d（4–5 人日），依据是在主干上量的：

- 来源 4 个包：过渡目录 3 个共 3043 行，仓库根 1 个 54 行；公共 API 557 行（过渡目录 459）；测试 2 个项目共 2149 行；要搬出 4 个项目。
- 换包名要扫的面：出现这一批 Qian 名字的代码、构建、清单与脚本文件 244 个（其中 .cs 177 个）；C# using 152 行，分布在 120 个文件；带 Qian 前缀的类型与成员名 10 个。Qian.Authz.Abstractions 有 104 个使用方文件，另有 8 个门禁样例。口径：git 跟踪的文本文件，去掉 `_import/qian/pm/`、`_import/qian/docs/`、`_import/qian/website/` 与仓库根 `docs/`；「这一批的 Qian 名字」指这一批要换的包名、命名空间与项目名，以及这一批的项目里声明的、带 Qian 前缀的类型名（以 Qian 开头的 class、interface、record、struct、enum、delegate）与方法名（以 Qian 开头，或是 `AddQian…`、`UseQian…`、`MapQian…`、`WithQian…`、`RequireQian…`）。
- 要合一的有 4 处：过滤表达式、判定主体、HTTP 与 gRPC 的强制执行点、两个 `Require…Permission`；另有引擎与中介的挂接方式、从 Kun.AspNetCore 搬来的权限扩展。
- 分配：换包名与搬目录 1d，类型合一 1d，强制执行点与权限扩展 1.5d，引擎挂接 0.5d，全量测试与文档 1d。

依赖 S1-KUN-026（B7）；下一批 S1-KUN-028（B9）依赖本任务。
