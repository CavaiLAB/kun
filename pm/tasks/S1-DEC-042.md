## 背景

2026-11-25 晚，产品负责人又定了一条，原文记在 `CavaiLAB/jiangxin` 的 [2026-11-25 平台级裁定](https://github.com/CavaiLAB/jiangxin/blob/c7b32a4dea2d1455fd2b9835e1cc0848c9d036c2/docs/decisions/2026-11-25-platform.md)（P75）。它与本仓库已接受的决策记录有一处出入。同一天较早的几条登记在 [S1-DEC-041](S1-DEC-041.md)，那个任务已经完成，不再改；本任务照它的写法登记这一条，括号里是平台级裁定的编号。ADR 的原文不改：对应的 ADR 末尾追加带日期的小节，受影响的条目前加标注。需求文档里受影响的条目前加带日期的标注，原文不删。

引号里是产品负责人的原话与问话。下面用到的几个说法：

- 「M1」是平台路线的里程碑：启用 `agent` 主体，能力目录先只读给 Agent 用，调用经 MCP 路由（[S1-DEC-038](S1-DEC-038.md) D25）。
- 「确认卡的最小一圈」是平台级裁定 P72 排的第一条线：平台上等人输入的任务，加一个要人确认的写能力，人点了才落库（S1-DEC-041 D7）。
- 「工作区服务」是匠心自己的一个服务，接它的 Web 端里 Agent 工作区的域名，把登录的人送进他自己的 Agent 实例（S1-DEC-041 D4）。

### 裁定（产品负责人，2026-11-25）

- D1 确认卡的最小一圈先用替身演示，不等 M1（P75）。问的是「确认卡这一圈先用替身演示、不等 M1，这样定吗？」，两个选项是「先用替身」「等 M1」，答「先用替身」。确认卡的最小一圈不等 M1 的 `agent` 主体与 MCP 路由，先用替身演示，和 M1 并行；M1 做好以后替身撤掉。与 [ADR-016](../../docs/adr/ADR-016-agent-boundary.md) D16.9 有出入：那里写「Agent 不直连 Qian 服务裸 URL，一律经 Higress MCP 路由」。同一口径的还有 [ADR-010](../../docs/adr/ADR-010-gateway-layers.md) §6 的 S4 一行、[PRD 第 7 章](../../docs/prd/07-s1-foundation.md) 7.9 节的「Agent 契约」与 [PRD 第 10 章](../../docs/prd/10-s4-agent.md) 10.2 节「调用」的第一条。这是 M1 之前的过渡，有意的偏离；M1 做好以后撤掉，D16.9 本身不改。

### 替身是什么

M1 做好以前，Agent 没有自己的主体，也没有经 MCP 路由调平台的那条路。替身是这段时间里代它向平台提出请求的一方。下面是做法，接口的形状是提议，随契约定稿：

- 实例里的工具不直接调平台，调的是匠心的工作区服务上一个给实例用的入口。
- 工作区服务认出是哪个实例、主人是谁，用自己的服务身份调平台的通用执行入口，并写明这次是代谁提出、处理人是谁。
- 平台照样不执行，生成一条等人输入的任务，等人点（S1-DEC-041 D7）。
- 本仓库一侧要多一种调法：有专门权限的服务主体声明这次是代某人提出。D7 里「不是人本人」写的是 Agent 或带着委托链；替身期间平台怎么认出要拦，是提议。

替身演示得了的：人点了才落库；审计里看得到是谁点的；实例一侧替人提交决定，平台会拒绝。演示不了的：「Agent 以谁的名义」和权限取交集；审计里「提出」那一条的主体是工作区服务，不是这个人的 Agent。

### 没有出入的与没有定的

- M1 自己的内容与完成标志不变。D16.9 本身不改：M1 做好以后，Agent 的调用照它走。
- ADR-015 §6 的 S4 一行写「Agent 经 Higress MCP 路由调用 Qian 能力」，是同向的目标描述，没有「一律」，没有标注，照 ADR-016 新追加的小节读。
- 这句答复没有覆盖的，都没有定：
  - 演示用的那条要人确认的能力放哪；谁做、什么时候做；拆出来的任务进不进看板。
  - 替身的接口形状。冻结的契约 `contracts/v0` 没有动。
  - M1 做好以后，替身那种调法是留给「服务要人点头」的场景，还是一起撤掉。
- 范围是整理者的读法：只定了「先用替身、不等 M1」这一件。
- 都还没有实现。看板上相关的只有预留 Operation 契约的 [S1-RT-007](S1-RT-007.md) 与验证主体模型和委托链的 [S1-AGT-003](S1-AGT-003.md)，都没有动；没有新建实现任务，没有改代码。
