## 背景

自 [S1-AZ-005](S1-AZ-005.md) 拆出，是[契约草案](../../docs/prd/specs/authz-remote-interface.md)第 13.1 节四个里的第三个。原任务背景里的「主体解析接 7.4.3 目录（组织 / 岗位 / 用户组归属）」归这里。它承接原任务验收的第 1、4 条。优先级沿用原任务的 P0；排期没有问过（[S1-DEC-048](S1-DEC-048.md) 问题 4）。

这一部分不在契约草案里展开，也不等远程授权接口的契约定稿。

现状：角色存储接受绑到组织、岗位、用户组上的角色，但求值不沿归属展开，授给组织的角色落不到成员头上。

S1-AZ-005 的进度日志里登记过给这一部分的口径，开工前先读。要点：

- 组织、岗位、用户组的绑定接进判定以后，归属的变化要进入快照失效，不然缓存会继续命中旧的角色集合。
- 这几种绑定上授予的增、改、撤，要按成员扇出递增身份修订，口径同 S1-AZ-009：提交以后在同一次调用里经身份端口递增，并同步抬高执行点的下限。S1-AZ-009 只处理了 user 主体。

## 验收

- [ ] IT（承接 S1-AZ-005 验收第 1 条）：把角色授予组织 X 后 X 下成员 ≤ 3 秒内获得权限；主归属变化后有效角色随之变化
- [ ] IT（R82，自 S1-AZ-003 移交，承接 S1-AZ-005 验收第 4 条）：把角色授予组织 X，X 下成员在 ≤ 3 秒内获得权限，移出组织后 ≤ 3 秒失效
- [ ] IT：岗位与用户组的归属同样接进判定。这一条是拆分时新写的：原任务的题目与背景写了组织、岗位、组三种，验收只写了组织
- [ ] IT：组织、岗位、用户组上的授予增、改、撤以后，受影响成员手里的旧令牌在 3 秒以内失效，口径同 S1-AZ-009。这一条是拆分时新写的，依据是 S1-AZ-005 日志里 2026-10-22 登记的口径
