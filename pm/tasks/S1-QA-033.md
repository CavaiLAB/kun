## 背景

产品负责人 2026-11-27 答第二张表「都按建议」（登记在 [S1-DEC-050](S1-DEC-050.md)）。第二张表第 5 条问的是本仓库里旧外壳、租户与成员页、平台控制台的代码与检查留不留，建议是「代码留在仓库里不删、不再改，不再进镜像和发布链；它们的 CI 只留登录页用得着的，其余停掉；相关任务里后端与部署的部分照做，页面的部分不做。」本任务做其中「停掉 CI、从镜像与发布链里拿掉」这一半。代码照旧留在仓库里，不删、不改。

同一天他发来的新方向（登记在 [S1-DEC-051](S1-DEC-051.md)）把登录页也放到匠心重新设计。所以「登录页用得着的」检查也只是暂时留着：留到匠心的新登录页跑通、照 [S1-IDP-032](S1-IDP-032.md) 的设计接上身份服务为止，之后这些检查换成什么，随那个设计定。

`.github/workflows/` 下的工作流逐个列在这里（对着 2026-11-27 的主干读的；每个工作流由 `ci.yml` 按 `scripts/ci_changes.py` 的区域调用）。「处理」一栏是整理时的归类，开工时照它做，有出入的写进日志：

| 文件 | 测的是什么 | 登录页用不用得着 | 处理 |
|---|---|---|---|
| `ci.yml` | 根工作流：变更检测、.NET 构建与测试、AOT、镜像自检、使用文档示例，并调用下面各个工作流；「CI 汇总」是必需检查 | 用得着（整体） | 留。去掉停掉的那几个作业，「CI 汇总」的名字不改 |
| `release.yml` | 维护者手动发 NuGet 包与 GitHub Release | 不相干 | 留。发布链里有没有只为旧外壳的包，见下面「镜像与发布链」 |
| `qian-docs-and-pm.yml` | 文档门禁、任务文件校验、看板生成 | 不相干 | 留 |
| `qian-docs-site.yml` | Kun 网站的构建、检查与发布 | 不相干 | 留。站上过时的 Qian 内容照去向表另做 |
| `qian-documentation.yml` | 事件声明与调用、CLI 文档模板、`docs/generated` 与源码的派生输出 | 不相干 | 留：命令行 `qian` 照旧维护 |
| `qian-surfaces.yml` | TypeScript 与 .NET 两边的声明式表面契约、诊断、市场规则与 profile 装载，用 `@qian/surfaces` 与 `qian` | 不相干 | 留：校验库与命令行照旧维护 |
| `qian-dev-tenant-ops.yml` | 租户运营宿主的后端走查（`scripts/dev-tenant-ops.sh smoke`，调运营 HTTP，不起页面） | 不相干 | 留：是后端 |
| `qian-directory-e2e.yml` | 用浏览器测前端框架业务包里的组织与人员选择器，经真实身份宿主的目录接口 | 用不着 | 停：只为成员一类页面的组件；目录接口本身由 .NET 的契约测试管 |
| `qian-tenant-ui.yml` | 租户运营页面（`@qian/tenancy-ui`）在开发宿主上的七步验收 | 用不着 | 停 |
| `qian-shell-federation.yml` | 外壳挂载与按需加载远程模块（Module Federation） | 用不着 | 停 |
| `qian-shell-auth.yml` | 真实身份服务上的外壳登录、多租户选择、切换租户、连接器登录、注册页主线，以及平台控制台与参考应用远程页面的用例；依赖方是旧外壳 | 用得着一部分 | 暂留：登录、选择租户、改密、连接器登录与注册页的用例留到新登录页跑通；只测外壳、平台控制台与远程页面的用例拿掉。登录用例离不开一个依赖方，旧外壳暂时照旧当依赖方用，或者换成不依赖外壳的最小依赖方，开工时定 |
| `qian-ui.yml` | 外壳与界面包的样式、类型、单测、依赖边界、循环依赖与构建（`pnpm ui:*`） | 用得着一部分 | 收窄：只留认证页 `@qian/identity-ui` 与它依赖的 `@qian/shell-kit`，以及注册页 `@qian/tenancy-signup-ui`；外壳、租户运营页面、参考应用的远程模块与目录验收页移出这些检查 |

注册页读作与登录页同属认证一类、一起去匠心，旧注册页的检查与旧登录页一样留到新页面跑通，这是整理时的读法。

镜像与发布链（`deploy/images/README.md`、`scripts/images.py`、`profiles/`）：

- 网关镜像里的外壳（`apps/qian-shell/dist/host`，送进 `/app/web/shell/`）与远程模块的制品不再送；网关宿主只在给了 `Shell:Root` 时托管外壳，不给即不托管（`hosts/Kun.Gateway.Host/README.md`）。
- 平台镜像里的 `identity/`（旧登录页）与 `signup/`（旧注册页）留到新页面跑通。
- `profiles/platform` 里的 `qian.bundle.shell@^1`（shell 组合包）要不要从缺省的装配里拿掉，开工时核对它对平台宿主的影响再定。
- NuGet 包 `Kun.Gateway.Shell` 已经发布过（托管外壳与 bootstrap 聚合），停不停发新版改变对外的承诺，不在本任务里定，列在[去向表](../../docs/package-and-docs-disposition.md)「要产品负责人定的」。

工作流与发布链的改动另开 PR，推送与合并照旧另问。估时是整理时的估计。
