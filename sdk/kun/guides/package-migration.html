#NuGet 包迁移指南

Markdown 链接
发布版本来源

本页由本仓库的发布标签生成，源文件为 docs/guides/package-migration.md（v2026.11.24）。Kun 文档与代码不一致处以代码为准（ADR-001 D1.8）；平台集成方式见内核与平台组件。

首个合并版发布后，从平台 0.x 或内核 2026.10.25 升级的项目可按以下步骤选择版本。内核档从 nuget.org 还原，平台档从 CavaiLAB 的 GitHub Packages 还原。beta 版本的两档包均从 GitHub Packages 还原。

  1. 在该版本的 GitHub Release 下载 NuGet.config 与 release-packages.json。前者列出准确的包源映射，后者列出该版本的全部包和档位。已有包源配置的项目合并相应条目。
  2. 使用有读取包权限的账号与令牌设置 KUN_PLATFORM_FEED_USER 和 KUN_PLATFORM_FEED_TOKEN，然后更新项目的 PackageReference。采用中央包管理的项目还需更新 Directory.Packages.props。
  3. 将使用的 Kun 包固定到同一个日历版本。使用内部接口的包之间声明精确版本依赖。运行 dotnet restore --configfile NuGet.config，再构建并执行项目的测试。

#内核包的替代项

停发的包使用方要做的调整
Kun.Audit命令审计契约使用 Kun.Audit.Abstractions，按宿主选择 Kun.Audit.EntityFrameworkCore 或 Kun.Audit.Postgres。
Kun.Auditing实体变更审计迁至 Kun.Audit.EntityFrameworkCore。
Kun.Dapper原生 PostgreSQL 通道使用 Kun.Data.Native.Postgres 与 Kun.Data.Native.Abstractions。逐条迁移自定义 SQL。
Kun.Infrastructure写侧直接使用业务 DbContext 与工作单元，读侧直接投影为查询 DTO。
Kun.MultiTenancy.EntityFrameworkCore引用 Kun.EntityFrameworkCore，更新注册扩展所在的命名空间。
Kun.Saga补偿编排器归档。依赖它的业务需要保留当前版本，或在应用中迁移编排与补偿逻辑后升级。
Kun.Sandbox沙箱已归档。先迁移宿主中的隔离实现，再移除包引用。
Kun.Storage引用 Kun.Storage.Abstractions，并按后端选择 Kun.Storage.Local、Kun.Storage.S3 或 Kun.Storage.Oss。

#同名包的行为变化

  • Kun.EventBus.RabbitMQ 使用组件事件信封与相应拓扑。升级前核对发布端与订阅端的交换机、路由键、消息形状和消费者组，协调切换生产与消费。
  • Kun.Audit.EntityFrameworkCore 属于平台档，升级时将这个包的源映射指向 GitHub Packages。实体审计与业务事务的接线见该版本的包说明。
  • Kun.AspNetCore 与 Kun.Grpc 不再自带权限判定。HTTP 端点的 RequireKunPermission 与 gRPC 的授权拦截器（AddKunAuthorizationInterceptor）由 Kun.Authorization.AspNetCore 提供，它属于平台档，从 GitHub Packages 还原。原来用这两处权限判定的项目要引用它，只从 nuget.org 还原的项目要为它映射源。没有登记授权拦截器时，Kun.Grpc 拒绝执行标了 [RequiresPermission] 的方法。
  • Kun.Gateway 提供类库。把宿主的可执行入口切到网关宿主，使用平台外壳时再引用 Kun.Gateway.Shell。选项类型 KunGatewayOptions 换成 Kun.Gateway.Abstractions 里的 GatewayConfiguration，ExternalIssuer、ExternalAudience、InternalIssuer 依次改名为 IdentityIssuer、IdentityAudience、Issuer。Redis 固定窗口计数器的类型（IRedisRateLimitStore、RateLimitHitResult、RedisRateLimitStoreOptions、RedisFixedWindowRateLimitStore）改在 Kun.RateLimit 命名空间，注册扩展 AddKunRedisRateLimitStore 改在 Kun.RateLimit.Extensions。
  • 租户上下文使用 Guid? 表示租户或平台作用域。处理消息与网络输入时先验证租户标识，数据库与既有消息的文本按原有格式读写。
  • Kun.MultiTenancy 不再提供可替换的租户解析器与选项：DefaultTenantResolver、ITenantResolver、ITenantIdSource、KunMultiTenancyOptions 与 AddKunMultiTenancy(Action<KunMultiTenancyOptions>) 已删除。宿主登记 AddKunMultiTenancy()，在认证之后挂载 UseKunMultiTenancy()。租户只从已认证主身份唯一的 tenant_id 读取，请求头不再作为来源，没有缺省租户回落。
  • Kun.Security 的 AddKunSecurity() 不再登记 ITenantContext，JwtTenantContext 已删除。需要租户上下文的宿主另调 AddKunMultiTenancy()。
  • IKunPlugin<TConfig> 的实现通过 ConfigTypeInfo 提供源生成的 JSON 元数据。使用 JsonSerializerDefaults.Web 保持配置属性名匹配规则。
  • HTTP 错误与进程内错误使用 Kun.Errors 定义的错误码和 ErrorDetail。依赖旧错误字面或响应结构的调用方需要同步更新解析逻辑。

各项公共 API、注册方法与部署变更见版本变更记录。
