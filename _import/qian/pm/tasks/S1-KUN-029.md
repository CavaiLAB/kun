## 背景

合并阶段 3（S1-KUN-021）的第 7 批，也是最后一批，迁移执行计划（仓库根 `docs/migration-plan.md` 第 4 节）的 B10：合并蓝图 ADR-023 D23.9 第六张表「只在 Qian 的平台组件」，加第四张表里的生命周期与调度，以及前面几批没有带走的宿主、工具、样例。这一批做完，过渡目录 `_import/qian/` 里不再有 .NET 项目。`Registry`、`Lifecycle` 两个根不加 `Plugins.` 中缀（D23.19 第 5 点）。命名照 D23.8，档位照 D23.7。

表外几件事：

- 宿主、工具、样例与测试（D23.9 表后那一段）：宿主 `_import/qian/hosts/Qian.Platform.Host`；样例 `_import/qian/samples/Qian.Sample.Crm`（它的界面 `qian-sample-crm-ui` 属于前端工作区，不随 .NET 项目搬）；工具 `_import/qian/tools/` 下的 Qian.Dev.Shell、Qian.Dev.TenantOps、Qian.Docs.Tool、Qian.Image.SelfCheck、Qian.Image.SelfCheck.Aot 与平台分析器 Qian.Build.Analyzers；测试 `_import/qian/tests/` 下的 Qian.Capabilities.Tests、Qian.Registry.Tests、Qian.Surfaces.Tests、Qian.Profiles.Tests、Qian.Docs.Tests、Qian.Lifecycle.Tests、Qian.Scheduler.Tests、Qian.Scheduler.TestHost、Qian.Sample.Crm.Tests、Qian.Shell.TestHost（外壳端到端的测试宿主）。过渡目录里随这一批搬出的 .NET 项目共 36 个（18 个包、18 个宿主、工具、样例与测试），七批里最多。Kun 的样例、基准与事件 Schema 导出工具留在原处（D23.9）。
- 平台分析器与诊断号：D23.10 把分析器诊断号与 MSBuild 属性算在跟着包名换的代码层。`Qian.Build.Analyzers`（QIAN0002–QIAN0006）与仓库根公共 API 门禁的 QIAN0001 一起换；它们写在仓库根 `Directory.Build.targets`（分析器的项目引用路径与 `WarningsAsErrors` 名单）、过渡目录的 `.editorconfig`、门禁自测与根 `AGENTS.md` 里。带 Qian 前缀的 MSBuild 属性还剩 `QianIsPackage`、`QianPackageId`（`_import/qian/scripts/dotnet_release.py` 读）与 `QianTrxPerModule`（两份 `tests/Directory.Build.props`，`ci.yml` 收测试结果用）；`QianKunGatewayDirectory` 由 B7 删掉。
- 过渡目录收尾：最后一个 .NET 项目搬走之后，`_import/qian/Qian.slnf`、`_import/qian/Directory.Build.props`、`_import/qian/Directory.Build.targets`、`_import/qian/tests/Directory.Build.props` 与按 `Qian.slnf` 工作的脚本（`dotnet_ci.py`、`check_plugin_manifests.py`）要么搬走、要么删掉；仓库根 `Directory.Build.targets` 里分析器作用域的过渡期那一条随之去掉，S1-DEC-038 D27 的出入消失。
- 过渡目录里的非 .NET 内容（任务看板、文档站、前端工作区、契约、Schema、TCK、组件与 profile、部署清单、文档、脚本等）不在七个批次的范围里；导入子目录什么时候消失（S1-KUN-021 验收最后一条）另定。

开工前要补的事：

- 蓝图 §1.2 的未核实事项落在这一域的：调度的工作循环只读了结构，没有读完实现。动 Qian.Scheduler 之前读完。
- 档位按依赖图复核（仓库根 `scripts/check_deps.py`，项目文件里的 `KunTier` / `KunRole`）：这一批的包都在平台档，现在没有例外；Qian.Plugin.Sdk → Qian.Surfaces.Abstractions 那条例外（规则 K）由 B4 去掉（S1-KUN-023），B4 若没去掉，这一批去掉。
- 静态能力目录并入：Kun.Mediator 里的 `CapabilityDescriptor` 与 `ICapabilityRegistry`（`src/Kun.Mediator/CapabilityRegistry.cs`）在这一批并进 Kun.Capabilities。B4 只给中介开权限行为的扩展点，不动它们。
- B4 留给这一批的：表面键 `SurfaceKeys` 由组件运行时移进 Qian.Surfaces.Abstractions；scope 种类的取值由平台档定，Registry、Profiles 的种类校验抽成平台档的常量。这几处随 Qian.Surfaces.Abstractions、Registry、Profiles 一起换包名。
- 对前端有没有影响，这一批碰到的最多：前端仓库按摘要钉着副本的 `_import/qian/schemas/v2/ui.schema.json`、`tck/surfaces/cases.json` 与 `contracts/v0/fixtures/capability-entry.valid.json` 都在表面与能力目录一域；`tck/runtime` 的说明、`packages/qian-cli` 的文档命令与测试、`profiles/`、`plugins/` 下 qian.capabilities、qian.lifecycle、qian.registry、qian.scheduler 等组件清单里的入口类型与程序集名都写着这一域的名字。外壳的端到端测试（`apps/qian-shell` 的 `vite.config.ts`、`scripts/e2e.mjs`、`playwright.auth.config.ts` 与 `e2e-auth/`）按路径起外壳测试宿主与平台宿主，镜像构建上下文 `deploy/images/jit.Dockerfile.dockerignore` 放行的是 `_import/qian/hosts/Qian.Platform.Host/**`。改之前先看。
- 组件版本：`_import/qian/plugins/` 下 system 级组件（`policy.tier` 为 system、`runtime.form` 为 module 的非骨架组件，口径同 `scripts/sign-system-revisions.py` 的签名清单）的文件夹里任何文件一改，目录摘要就变：清单里的入口类型与程序集名随包换、README 改一个字都算。按 S1-DEC-037 的裁决（R167），要连带升该组件的版本，版本号继续唯一对应文件夹的内容。这一批碰到的 system 级组件：qian.capabilities、qian.lifecycle、qian.registry。
- 文档：仓库根 `docs/` 写到这一域的很少；`AGENTS.md` 里写过渡目录、`Qian.slnf` 与分析器作用域的段落在这一批改掉。

估算 8d（7–9 人日），依据是在主干上量的：

- 来源 18 个包，共 13808 行（其中迁移 2532 行）；公共 API 1567 行；宿主、工具、样例与测试 18 个项目共 23021 行（Qian.Sample.Crm.Tests 一个就 10793 行）；要搬出 36 个项目。
- 换包名要扫的面：出现这一批 Qian 名字的代码、构建、清单与脚本文件 510 个（其中 .cs 335 个）；C# using 340 行，分布在 183 个文件；带 Qian 前缀的类型与成员名 15 个。
