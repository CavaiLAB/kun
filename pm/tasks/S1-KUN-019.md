## 背景

ADR-023 D23.15 的阶段 1。2026-11-17 产品负责人裁定合并后的仓库是 `CavaiLAB/kun`、迁移现在开始（S1-DEC-038 D17），本任务随之改写：目标仓库由 `idadawn/kun` 换成 `CavaiLAB/kun`，两个旧仓库都要导入；不再等「初步可用」里程碑收口。

做法见迁移执行计划（`CavaiLAB/kun` 的 `docs/migration-plan.md`），本任务对应其中的 B1 与 B2：B1 是一个 PR，B2 拆成几个 PR：

- 用子树合并带历史导入，不改写历史，原提交的 SHA 保留。两个来源先各落在一个过渡目录里：原 Kun 在 `_import/kun/`，原 Qian 在 `_import/qian/`，两棵树先各用各的构建基线；B2 把原 Kun 提到仓库根。
- 先导入、后冻结。B1 合入之后两个旧仓库进入收口期，只收在途任务的收尾与紧急修复。B2 从产品负责人宣布冻结开始：两个旧仓库写明去处，归档，然后最后一次同步，再修绿原 Kun 的检查、改指看板与文档站、整理。最后一次同步合入之前，过渡目录里的文件不改名、不搬动、不改内容。
- 这一步只搬家，不改任何包名。目标布局与历史处理见 D23.13。

蓝图没有写许可证字段在哪个阶段统一。本任务按 B2 统一为 MIT 处理（D23.11），开工时如有异议先提出来。

估算是占位：蓝图写的是「数周量级，没有拆解估算」，构建并轨结束后按域建任务再估。

- [x] `idadawn/kun` 与 `idadawn/qian` 的 `main` 带历史导入 `CavaiLAB/kun`，原提交的 SHA 保留；原 Kun 落在 `_import/kun/`，原 Qian 落在 `_import/qian/`，两边顶层 14 个同名项不直接叠放（D23.13 第 2 点）；原 Kun 的版本标签带过去
- [x] 按执行计划第 5 节逐项核对并写进 PR 正文：祖先关系与提交数、导入提交上的树对象、标签、文件历史抽查、忽略规则与换行规则没有改变导入的文件
- [x] 两棵树在 `CavaiLAB/kun` 的托管 runner 上各自通过原有的全部检查；跑不起来的逐个列出原因与去处
- [x] 这一步不改任何源码与包名

B2 切换与整理：

- [x] 冻结后 `idadawn/qian` 的 `README.md` 写明去处，`idadawn/qian` 归档为只读，然后做最后一次同步并核对树（`idadawn/kun` 的收尾见 S1-KUN-018）

- [x] 原 Kun 由 `_import/kun/` 提到仓库根
- [x] 任务文件与文档里的历史 `#N` 改写：原 Qian 的写成 `idadawn/qian#N`，原 Kun 的写成 `idadawn/kun#N`（D23.13 第 3 点，S1-DEC-038 Q1）

- [x] 文档站「Kun 框架」镜像小节撤销，改为同仓来源；Kun 文档里写给特定下游的内容改写后再进站；平台文档站（`CavaiLAB/jiangxin`）取本仓库文档的范围随之调整
- [x] Kun 的 17 份 ADR 移入 `docs/adr/kun/`，引用时写「Kun ADR-0xx」；新 ADR 从 ADR-024 接着编（D23.13 第 4 点）
- [x] Kun 仓库里的自管任务队列与第三方生成的代理配置删除，任务管理统一到 `pm/`（D23.13 第 6 点）
- [x] 许可证统一为 MIT：`PackageLicenseExpression`、各 `package.json` 的 `license` 与仓库的许可证文件
